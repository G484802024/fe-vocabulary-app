# プログラムの基本要素
variable|変数|Variable|变量|処理中に読み書きする値を、名前などで参照できるようにしたもの。|变量让程序通过名字读取或更新一个值。|用 total 保存当前已经累计的订单金额。
constant|定数|Constant|常量|プログラム内で固定の値として扱い、通常の代入で変更しないもの。|常量用来表示程序运行中保持不变的值。|把一周的天数 7 声明为常量。
assignment|代入|Assignment|赋值|式を評価して得た値を、指定した記憶先に設定する操作。|赋值将计算结果写入变量等指定位置。|将当前计数加一后的结果重新存到计数器。
operator|演算子|Operator|运算符|値の計算、比較、組合せなどの処理を指定する記号や語。|运算符表示对值进行的操作，例如加法、比较或逻辑判断。|使用 + 将商品单价与配送费相加。
expression|式|Expression|表达式|値や処理の指定を組み合わせ、評価すると値が得られる記述。|表达式求值后产生一个结果。|使用单价乘数量的表达式得到小计。
data-type|データ型|Data Type|数据类型|値が取り得る範囲や、その値に適用できる操作を定めた分類。|数据类型约束可表示的值及其可用操作。|用整数类型保存库存件数，用字符串类型保存商品名称。
scope|スコープ|Scope|作用域|宣言された名前を、その名前で参照できるプログラム上の範囲。|作用域决定变量或函数名称在哪些代码范围内可见。|函数内部声明的临时变量在函数外通常不可直接访问。
lifetime|変数の生存期間|Variable Lifetime|变量生存期|実行中に、変数の記憶領域や値が保持される期間。|变量生存期描述变量的存储何时出现、何时释放。|一次函数调用结束后，普通局部变量的存储通常可以回收。
# 関数とエラー処理
function|関数|Function|函数|必要な入力を受け取り、定義された処理を一まとまりとして呼び出せるもの。|函数封装一段可以调用的处理，可以接收输入并返回结果。|调用计算运费的函数，传入重量和配送地区。
parameter|仮引数|Parameter|形参|呼出し時に渡される値を受け取るため、処理の定義に書く名前。|形参在函数定义中声明，用来接收调用方提供的值。|在计算运费的函数定义里写 weight，用它接收商品重量。
argument|実引数|Argument|实参|関数などを呼び出す際に、呼出し側が指定する具体的な値や式。|实参是调用函数时实际传入的数据。|调用运费函数时传入重量 2 千克。
return-value|戻り値|Return Value|返回值|呼び出された処理が終了時に呼出し元へ返す結果の値。|返回值把函数的计算结果交还给调用者。|运费函数把算出的 12 元返回给结账页面。
exception|例外|Exception|异常|処理の続行を妨げる状況などを、通常とは異なる制御経路で伝えるもの。|异常让程序通过专门的控制流程报告错误或特殊情况。|读取一个已被删除的文件时，读取函数报告异常。
exception-handler|例外ハンドラ|Exception Handler|异常处理器|異常を受け取ったときに、回復や通知などの対応を行う処理。|异常处理器捕获异常，并决定如何恢复、记录或报告问题。|文件读取失败时捕获异常并向用户显示“文件已移动”。
callback|コールバック|Callback|回调|別の処理に渡しておき、その処理から決められた時点で呼び出してもらう関数など。|回调是传给另一段程序的函数，由接收方在需要时调用。|上传完成后执行预先注册的回调来显示成功提示。
side-effect|副作用|Side Effect|副作用|結果の値を返すこととは別に、外部の状態を変更したり外部と入出力したりすること。|副作用是函数求值时对外界产生的影响，例如写文件、改外部状态或发送请求。|保存函数在返回成功标志的同时写入文件。
# オブジェクト指向
oop|オブジェクト指向プログラミング（OOP）|Object-oriented Programming|面向对象编程|状態と操作をまとめた対象の協調によって、プログラムを構成する考え方。|面向对象编程将数据及其操作放在对象中，让对象协同完成任务。|订单对象保存商品清单，并提供添加商品和计算合计的操作。
class|クラス|Class|类|共通する状態の項目や操作を、オブジェクトの型としてまとめて定義したもの。|类定义一类对象可包含的数据和可执行的方法。|定义商品类，规定每个商品都有名称、价格和改价方法。
instance|インスタンス|Instance|实例|定義された型を基に実際に生成され、個別の状態を持つオブジェクト。|实例是从类创建出来的具体对象，各实例可保存各自的状态。|键盘和鼠标可以分别是商品类的两个实例。
method|メソッド|Method|方法|クラスやオブジェクトに関連付けられ、そこに定義された操作。|方法是定义在类或对象上的操作。|调用购物车对象的方法来添加一件商品。
encapsulation|カプセル化|Encapsulation|封装|状態と処理を一つにまとめ、外部から操作する手段を制限すること。|封装将数据和操作放在一起，并限制外部直接访问内部细节。|账户余额只允许通过存款和取款方法修改。
inheritance|継承|Inheritance|继承|既存の型の属性や操作を、新しい型が引き継いで使える仕組み。|继承让子类复用父类定义，并可加入自身特点。|电子书类继承出版物类的标题属性，再增加文件格式。
polymorphism|多相性（ポリモーフィズム）|Polymorphism|多态|共通の操作を呼び出しても、対象の型などに応じて異なる処理を行える性質。|多态让调用者使用同一个操作，不同类型可执行各自的实现。|同一个付款操作可由银行卡类和电子钱包类分别实现。
override|オーバーライド|Method Overriding|方法重写|親の型にある操作の実装を、子の型で同じ契約を保って定義し直すこと。|子类重写继承的方法，使该方法在子类对象上执行子类定义的行为。|电子书类重写获取交付信息的方法，返回下载链接。
overload|オーバーロード|Method Overloading|方法重载|同じ名前の操作を、引数の型や個数などが異なる形で複数定義すること。|方法重载允许用同一个方法名声明不同参数列表，具体规则取决于编程语言。|分别声明接收一个文件路径和接收路径加编码的方法。
composition|コンポジション|Object Composition|对象组合|あるオブジェクトが別のオブジェクトを部品として持ち、その機能を使って構成されること。|对象组合让对象包含并使用另一个对象来实现功能。|结账对象使用一个运费计算对象来取得配送费用。
# コードの変換と実行
source-code|ソースコード|Source Code|源代码|開発者がプログラムの処理を、プログラミング言語の記法で記述したもの。|源代码是开发者用编程语言写出的程序文本。|在 Java 文件中编写计算账单的方法。
machine-code|機械語|Machine Code|机器码|処理装置が直接解釈して実行できる命令の表現。|机器码是处理器可直接执行的指令编码。|为 x86 生成的机器码要在兼容该指令集的处理器上运行。
assembly-language|アセンブリ言語|Assembly Language|汇编语言|機械語に近い命令を、人が扱いやすい短い記号などで記述する言語。|汇编语言用助记符等文本表示与机器指令紧密对应的操作。|用 MOV 等助记符编写寄存器数据移动指令。
assembler|アセンブラ|Assembler|汇编器|低水準の命令を記号で書いたプログラムを、機械語などに変換するツール。|汇编器把汇编语言源码转换为机器指令等目标内容。|将写好的汇编文件生成可供链接的目标文件。
compiler|コンパイラ|Compiler|编译器|ある言語で書かれたプログラムを、実行前などに別の言語や命令形式へ変換するソフトウェア。|编译器将代码转换为另一种表示，例如机器码或中间代码。|把 C 源文件编译成目标文件。
interpreter|インタプリタ|Interpreter|解释器|プログラムの記述や中間表現を読み取り、その意味に従って実行する処理系。|解释器读取源代码或中间表示并执行其含义，具体实现可能也包含编译。|在交互环境中输入一行脚本并立即查看结果。
linker|リンカ|Linker|链接器|複数の翻訳済みファイルやライブラリを結合し、外部参照などを解決するツール。|链接器合并目标文件和库，并匹配跨文件的函数或数据引用。|把主程序与字符串处理库链接成一个可执行文件。
bytecode|バイトコード|Bytecode|字节码|仮想機械などで扱えるようにした、機械語に近い中間命令の表現。|字节码是供虚拟机处理的中间指令格式。|Java 编译器将源文件生成 JVM 可运行的 class 文件。
runtime|実行時環境|Runtime Environment|运行时环境|プログラムの実行に必要な機能やライブラリを提供する仕組み。|运行时环境提供程序执行所需的支持，包括内置库和代码执行能力。|使用 Node.js 环境运行 JavaScript 脚本。
jit|実行時コンパイル（JIT）|Just-in-time Compilation|即时编译|プログラムの実行中に、必要になった処理を機械語などへ変換する方式。|即时编译在程序运行期间转换代码，常用来加速反复执行的部分。|浏览器为多次运行的脚本函数生成更快的机器码。
# 開発プロセス
sdlc|ソフトウェア開発ライフサイクル（SDLC）|Software Development Life Cycle|软件开发生命周期|ソフトウェアを計画し、作り、利用を支えていく一連の段階を捉えたもの。|软件开发生命周期用阶段描述软件从规划到设计、实现、测试和维护的过程。|团队按阶段安排预约系统从需求分析到上线维护的工作。
waterfall|ウォータフォールモデル|Waterfall Model|瀑布模型|要求や設計などの工程を順に進め、前の工程の成果を基に次の工程を行う開発モデル。|瀑布模型将项目分成依次推进的阶段，后一阶段使用前一阶段的成果。|在明确并评审需求后，团队依次完成设计、实现和测试。
agile|アジャイル開発|Agile Software Development|敏捷开发|短い間隔で動く成果を確認し、関係者の意見や変化に応じて開発を進める考え方。|敏捷开发用短周期交付和反馈，持续调整产品方向。|每隔两周展示可用的新功能，再按用户反馈安排下一批工作。
scrum|スクラム|Scrum|Scrum 框架|短い期間で成果を作り、定められた責任やイベントを通じて改善するチームの枠組み。|Scrum 是一种敏捷框架，用明确的职责、事件和工件支持团队检视与调整。|团队在每个 Sprint 结束时检视成果，并在回顾中调整合作方式。
sprint|スプリント|Sprint|Sprint 迭代周期|定めた目標に向けて作業し、使える成果を積み上げる一か月以内の固定期間。|Sprint 是 Scrum 中固定长度的工作周期，最长一个月。|团队用两周完成图书检索的可用版本。
prototype|プロトタイプ|Prototype|原型|完成品を作る前に、使い方や技術上の見通しを確かめるための試作物。|原型让团队在完成正式产品前试验交互方式或验证技术可行性。|制作一个可点击的预约流程原型，让用户试操作。
requirements-definition|要件定義|Requirements Definition|需求定义|利用者の課題を整理し、システムに必要な機能や満たすべき条件を明らかにする活動。|需求定义明确系统应提供哪些功能、满足哪些限制。|约定系统允许学生在线选课，并须在提交后显示确认结果。
functional-requirement|機能要件|Functional Requirement|功能需求|利用者や他システムに対して、システムが何を行うべきかを定める条件。|功能需求说明系统应提供的操作、响应或业务处理。|图书系统必须支持按书名检索馆藏。
nonfunctional-requirement|非機能要件|Non-functional Requirement|非功能需求|処理速度、信頼性、利用しやすさなど、機能の品質や制約を定める条件。|非功能需求规定性能、可用性或其他系统质量和限制。|在规定访问量下，馆藏搜索须在两秒内返回结果。
user-story|ユーザストーリー|User Story|用户故事|利用者の立場から、求める行動とその価値を短く記述したもの。|用户故事以使用者为出发点，说明他想做什么以及这样做的价值。|“作为读者，我想在线续借，以便不用到馆办理。”
# バージョン管理
vcs|バージョン管理システム（VCS）|Version Control System|版本控制系统|ファイルの変更履歴を記録し、過去の状態を確認したり共同作業を行ったりする仕組み。|版本控制系统保存项目的修改历史，支持回看、协作与合并。|开发者查看结账功能上周的代码版本。
git|Git|Git|Git 版本控制工具|各作業者の手元にも変更履歴を持てる、分散型の版管理ツール。|Git 是分布式版本控制工具，每位开发者都可以在本地保存和使用项目历史。|在无网络时提交本地修改，恢复联网后同步给团队。
repository|リポジトリ|Repository|代码仓库|ファイルとその変更履歴などを一まとまりに保管する場所。|代码仓库保存项目文件、版本历史和相关信息。|为课程预约网站建立一个 Git 仓库，供团队共同维护。
git-commit|コミット（バージョン管理）|Version Control Commit|版本提交|変更を説明などとともに版管理の履歴上に記録したもの。|版本提交将一组修改记录为一个历史节点，并可附上说明。|记录一次修复预约时间显示问题的修改。
branch|ブランチ|Branch|分支|変更履歴の中で、他の作業と分けて更新を進めるための系統。|分支提供一条可单独推进的开发线。|在新分支完成词汇搜索后，再把修改合回主分支。
merge|マージ|Merge|合并|分かれて進んだ変更を、一つの履歴または作業結果に取り込む操作。|合并将不同分支中的改动纳入同一个结果。|把词汇搜索分支和错题本分支的改动合到主分支。
merge-conflict|マージ競合|Merge Conflict|合并冲突|同じ箇所に互いに両立しない変更があり、自動では一つにまとめられない状態。|合并冲突发生在版本工具无法自动协调不同改动时，需要人工选择或结合。|两人对同一条按钮文案作了不同修改，合并时需要选定最终文本。
tag|タグ（バージョン管理）|Version Control Tag|版本标签|履歴上の特定の版を名前で参照するため、その版に付ける目印。|版本标签给某个提交加上便于识别的名称。|把正式发布时的提交标记为 v1.0.0。
pull-request|プルリクエスト|Pull Request|拉取请求|作業した変更の確認を依頼し、別の開発系統に取り込むことを提案する機能。|拉取请求提交一组改动，供团队讨论、检查并决定是否合并。|为新增搜索功能发起拉取请求，请同事评审。
diff|差分（diff）|Diff|差异对比|二つの版の間で、追加、削除、変更された箇所を示す情報。|差异对比显示两个版本之间具体增删了哪些内容。|审查者通过差异对比确认只修改了预约页面。
# テストの目的と段階
unit-test|単体テスト|Unit Testing|单元测试|関数やクラスなど、個別の小さな構成要素の動作を確認するテスト。|单元测试针对函数或类等小单元验证其行为。|验证计算折扣的函数在不同订单金额下返回正确折扣。
integration-test|結合テスト|Integration Testing|集成测试|複数の構成要素を接続したときに、受渡しや連携が正しく行われるかを確認するテスト。|集成测试检验模块连接后能否正确交换数据和协作。|测试预约接口能把选择的日期正确保存进数据库。
system-test|システムテスト|System Testing|系统测试|構成要素を組み合わせた全体について、システム要件を満たすか確認するテスト。|系统测试从整体检查系统是否达到既定要求。|在接近正式环境的配置中验证图书借还、搜索和报表功能。
acceptance-test|受入れテスト|Acceptance Testing|验收测试|利用者側の受入れ条件を満たし、引渡し可能かどうかを判断するためのテスト。|验收测试依据约定的验收标准，判断交付成果是否符合业务需要。|由图书馆工作人员按约定流程验证新系统能否办理借还。
regression-test|回帰テスト|Regression Testing|回归测试|修正や追加の後に、以前は正常だった動作が壊れていないかを確認するテスト。|回归测试检查代码变更是否破坏原先正常的功能。|改进词汇搜索后，重新验证收藏和错题记录仍能保存。
performance-test|性能テスト|Performance Testing|性能测试|応答時間や処理量などを測り、要求された処理能力を満たすか確認するテスト。|性能测试通过测量响应时间、吞吐量等指标评估性能。|测量首页在规定并发访问数下的加载时间。
load-test|負荷テスト|Load Testing|负载测试|想定する利用量の範囲で負荷をかけ、動作や処理能力を確認するテスト。|负载测试施加预期范围内的请求量，以观察系统的表现。|用预估的开课时访问量检查选课系统的响应。
stress-test|ストレステスト|Stress Testing|压力测试|想定する範囲を超える負荷などを与え、限界時の挙動や回復を確認するテスト。|压力测试在超出预期负载或资源紧张时检查系统如何失效和恢复。|逐步加大访问量，观察系统饱和后是否能正常恢复。
e2e-test|エンドツーエンドテスト（E2E）|End-to-end Testing|端到端测试|利用者の操作の始まりから、関係する処理を通った最終結果までを確認するテスト。|端到端测试用完整业务流程验证从操作到结果的各环节。|模拟读者搜索、预约并查看预约成功记录。
smoke-test|スモークテスト|Smoke Testing|冒烟测试|詳しい検証に入る前に、起動や主要機能が動くことを短時間で確かめるテスト。|冒烟测试快速验证构建后的软件能否运行，以及主要功能是否可用。|安装新构建后先确认能打开首页并进入答题页面。
# テストケースの設計
black-box|ブラックボックステスト|Black-box Testing|黑盒测试|内部の実装を基準にせず、仕様に示された入力と出力などに基づいて行うテスト。|黑盒测试根据规格检查对外行为，不依赖内部代码结构。|只根据计价规则输入不同购买数量，核对页面显示的总价。
white-box|ホワイトボックステスト|White-box Testing|白盒测试|プログラム内部の文や分岐などの構造を利用して行うテスト。|白盒测试利用代码内部结构设计用例。|阅读代码后，为其中每条判断分支安排相应输入。
equivalence-partitioning|同値分割|Equivalence Partitioning|等价类划分|同じように扱われる入力をグループに分け、各グループの代表を選ぶ設計技法。|等价类划分按预期处理行为归类输入，从各类中挑选代表测试。|把年龄分为未成年、成年人和无效输入，每类选一个年龄测试。
boundary-value|境界値分析|Boundary Value Analysis|边界值分析|入力の範囲や分類が切り替わる境目とその付近を選んで検証する技法。|边界值分析重点检查取值范围交界处及其附近，因为边界常出现差一错误。|限购 5 件时，检查购买 4、5 和 6 件的结果。
test-case|テストケース|Test Case|测试用例|一つの確認に必要な前提、入力、操作、期待される結果などをまとめたもの。|测试用例说明在什么条件下做什么操作，以及预期得到什么结果。|给出一份空购物车，点击结算，预期显示添加商品的提示。
coverage|コードカバレッジ|Code Coverage|代码覆盖率|実行した確認によって、プログラムの文や分岐などがどの程度通ったかを表す指標。|代码覆盖率衡量测试执行过哪些代码元素，例如语句或分支。|报告显示 90% 的语句在测试过程中至少运行过一次。
statement-coverage|命令網羅|Statement Coverage|语句覆盖率|プログラム内の実行可能な文のうち、テストで実行された文の割合。|语句覆盖率按执行过的语句数量衡量覆盖程度。|为未执行过的错误提示语句补上一个触发错误的用例。
branch-coverage|分岐網羅|Branch Coverage|分支覆盖率|条件判定などから進める経路のうち、テストで通過した分岐の割合。|分支覆盖率统计测试跑到了哪些分支结果。|对库存是否足够的条件，分别测试成立和不成立。
test-stub|テストスタブ|Test Stub|测试桩|テスト対象から呼び出される部品の代わりに、決めた応答を返す仮の部品。|测试桩替代被测模块的依赖，并提供可控返回值。|用一个固定返回“有库存”的桩替代实际库存接口。
test-driver|テストドライバ|Test Driver|测试驱动程序|本来の呼出し元の代わりにテスト対象を起動し、入力を与えるプログラム。|测试驱动程序模拟调用方，向被测模块输入数据并收集结果。|在结账页面完成之前，用测试程序直接调用计价模块。
# ソフトウェアの構成と開発基盤
api|API|Application Programming Interface|应用程序编程接口|他のプログラムが機能を利用するための呼出し方やデータ形式を定めた接点。|API 约定一个程序如何调用另一个程序或模块的功能。|图书应用用 API 向馆藏服务查询某个书号。
library|ライブラリ|Software Library|软件库|他のプログラムから利用できるよう、共通の処理を部品としてまとめたもの。|软件库提供可复用的功能，由应用按需调用。|应用调用日期库来格式化借阅到期日。
framework|フレームワーク|Software Framework|软件框架|アプリケーションの基本構造や処理の流れを提供し、必要な部分を追加して開発できる仕組み。|软件框架提供应用结构和执行流程，开发者按其约定补充业务代码。|Web 框架把收到的请求分派给开发者写好的处理函数。
module|モジュール|Module|模块|プログラムの中で、役割に沿ってまとめられ、ほかの部分と区別できる構成単位。|模块按职责组织代码，并定义如何与其他部分交互。|将计价、用户管理和搜索各自放在独立模块。
coupling|結合度|Coupling|耦合度|異なる構成単位どうしが、どの程度互いの情報や実装に依存しているかを表す尺度。|耦合度衡量模块之间的依赖程度，依赖越强，改动越容易互相影响。|更换支付模块后，订单模块若无须了解其内部实现，说明两者耦合较低。
cohesion|凝集度|Cohesion|内聚度|一つの構成単位に含まれる処理やデータが、共通の目的にどの程度まとまっているかを表す尺度。|内聚度衡量一个模块内部各部分是否集中完成同一职责。|计价模块只负责费用计算，内部职责比较集中。
build|ビルド|Software Build|软件构建|ソースや資源を変換・組み合わせ、実行や配布に使える成果物を作る作業。|软件构建将源码和资源处理成可运行或可分发的产物。|把网页源码打包成可部署的静态文件。
dependency|依存関係（ソフトウェア）|Software Dependency|软件依赖|あるソフトウェアが動作や開発のために、別の部品やパッケージを必要とする関係。|软件依赖表示项目需要其他软件组件才能开发或运行。|报表模块需要安装电子表格库才能生成报表。
package-manager|パッケージマネージャ|Package Manager|包管理器|必要な部品の取得、導入、版の選択、更新などを管理するツール。|包管理器根据项目声明安装依赖，并协调依赖版本。|团队用 npm 安装构建网页项目需要的依赖包。
ci|継続的インテグレーション（CI）|Continuous Integration|持续集成|変更を頻繁に統合し、そのたびに自動で組立てや検査を行う開発の実践。|持续集成通过频繁合入改动并自动构建和测试，尽早发现集成问题。|每次推送代码后，自动运行题库检查和答题测试。
