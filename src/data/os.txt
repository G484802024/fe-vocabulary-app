# 実行の単位と状態
process|プロセス|Process|进程|実行中のプログラムを、専用のアドレス空間や割り当てられた資源とともに管理する単位。|进程是系统管理运行中程序及其内存和资源的单位。|打开两个独立的终端程序时，系统可为它们分别创建进程。
thread|スレッド|Thread|线程|同じ実行環境内のメモリや資源を共有し、独立して命令を実行できる流れ。|同一进程的线程共享地址空间等资源，各自有独立的执行进度。|浏览器可用一个线程处理界面，另一个线程进行后台计算。
pcb|プロセス制御ブロック（PCB）|Process Control Block|进程控制块|実行の状態、識別番号、保存したレジスタなどを、OSが管理するためのデータ構造。|操作系统在进程控制块中保存进程的标识、状态等管理信息。|切换执行对象时，系统记录原进程的寄存器状态。
pid|プロセスID（PID）|Process Identifier|进程标识符|OSが管理する実行中のプログラムの個々の実体を識別する番号。|PID 在系统当前运行的进程中标识某个具体进程，退出后编号可能被复用。|用任务管理器查看占用 CPU 的进程编号。
ready|実行可能状態|Ready State|就绪态|実行に必要な条件がそろい、プロセッサを割り当てられるのを待つ状態。|就绪进程已有运行所需条件，只等调度器分配 CPU 时间。|刚提交的计算任务可以在就绪队列里等待执行。
running|実行状態|Running State|运行态|プロセッサを割り当てられ、命令を実際に処理している状態。|处于运行态的执行单位当前正在使用 CPU。|某个线程正在处理图片时处于运行态。
blocked|待ち状態（ブロック状態）|Blocked State|阻塞态|入出力の完了など、特定の事象が起きるまで実行を進められない状態。|阻塞表示当前还不具备继续运行的条件，单纯分配 CPU 也无法推进。|程序等待用户输入时，相关线程可处于阻塞态。
context-switch|コンテキストスイッチ|Context Switch|上下文切换|実行を切り替えるとき、現在のレジスタなどを保存し、次の実行対象の状態を復元する処理。|上下文切换保存当前任务状态，并恢复下一任务之前的执行现场。|一个进程的时间片用完时，系统可切换到另一个进程。
zombie|ゾンビプロセス|Zombie Process|僵尸进程|処理は終了したが、親が終了情報をまだ受け取っていないため管理表に残っている実体。|在类 Unix 系统中，子进程退出后若父进程还未回收退出状态，会暂时留下僵尸记录。|父进程执行等待操作后，退出子进程的僵尸条目消失。
# CPUの割当て
scheduler|スケジューラ|Scheduler|调度器|実行可能な仕事の中から、次にプロセッサを使うものを方針に従って選ぶ機構。|调度器按规则决定哪个就绪任务接下来使用 CPU。|系统可优先安排交互应用的线程以提高响应速度。
time-slice|タイムスライス|Time Slice|时间片|一つの実行対象に連続してプロセッサを使わせるために割り当てる時間の区切り。|时间片是系统给某个任务的一段 CPU 执行时间。|时间片结束时，系统可让另一个任务开始执行。
preemption|プリエンプション|Preemption|抢占|現在の処理が自発的に譲らなくても、OSが実行を中断して別の処理に割り当て直すこと。|抢占让操作系统能暂停当前任务，及时切换到另一任务。|高优先级的音频线程就绪后，系统可以抢占普通计算任务。
fcfs|先着順スケジューリング（FCFS）|First-Come, First-Served Scheduling|先来先服务调度|実行を要求した順番に、先に到着した仕事から処理する方式。|先来先服务按任务到达顺序分配执行机会。|批处理队列可以依次运行先提交、后提交的作业。
round-robin|ラウンドロビン方式|Round-Robin Scheduling|轮转调度|実行可能な仕事に一定の時間を順番に割り当て、終わらなければ列の末尾に戻す方式。|轮转调度依次给就绪任务时间片，未完成的任务等待下一轮。|两个计算任务可以轮流使用同一个 CPU 核心。
priority-scheduling|優先度スケジューリング|Priority Scheduling|优先级调度|待っている仕事に設定された重要度の順位を基に、次の実行対象を選ぶ方式。|优先级调度按任务的优先级决定执行顺序。|实时采集线程可排在低优先级的后台整理任务之前。
shortest-job-first|最短ジョブ優先（SJF）|Shortest Job First|最短作业优先调度|処理時間の見積りが最も短い仕事を先に実行する方式。|最短作业优先依据估计运行时长安排任务，短任务先执行。|若一组作业同时就绪且耗时可估计，可先安排只需几秒的检查任务。
starvation|飢餓状態|Starvation|饥饿状态|他の仕事ばかりが優先され、ある実行対象に必要な資源が長時間割り当てられない状態。|饥饿表示任务因长期得不到资源而无法继续。|高优先级作业不断进入时，某个低优先级作业可能一直等不到 CPU。
# 並行処理の調整
critical-section|クリティカルセクション|Critical Section|临界区|共有データにアクセスするため、同時に実行できる主体を制限する必要があるコードの部分。|临界区是访问共享资源、需要受并发保护的代码片段。|多个线程递增共享计数时，把读数、加一和写回放在同一个临界区内。
mutex|ミューテックス|Mutex|互斥锁|同時に一つの実行主体だけが保護対象へ入れるよう、取得と解放で制御する機構。|互斥锁在同一时刻只允许一个执行者持有，用于保护共享数据。|线程改写共享列表前先拿锁，改完后释放。
semaphore|セマフォ|Semaphore|信号量|取得可能な許可の個数を数値で管理し、空きがなければ実行を待たせる同期機構。|信号量用一个计数表示剩余许可，可限制同时进入的任务数量。|将许可数设为 3，使同时使用某资源的任务最多有三个。
deadlock|デッドロック|Deadlock|死锁|複数の実行主体が互いの持つ資源を待ち、どの主体も処理を進められなくなる状態。|死锁发生时，各任务相互等待对方释放资源，形成无法自行解除的等待。|线程甲持有锁 A 等待锁 B，同时线程乙持有锁 B 等待锁 A。
race-condition|競合状態|Race Condition|竞态条件|共有対象への処理の結果が、制御されていない実行順序やタイミングによって変わる状態。|竞态条件指程序结果依赖并发任务的实际执行时序，可能出现错误。|两个线程同时读取并增加同一计数，最终可能只增加一次。
atomic-operation|アトミック操作|Atomic Operation|原子操作|他の実行主体から途中の状態を観測されず、分割できない一つの処理として扱われる操作。|原子操作对并发观察者表现为一次不可拆分的变化。|用原子递增更新多个线程共享的请求计数。
spinlock|スピンロック|Spinlock|自旋锁|取得に失敗したときに眠って待つ代わりに、短い間隔で取得を試し続ける排他機構。|自旋锁的等待者反复尝试获取锁，会消耗 CPU，适合预计持锁很短的场合。|内核可用自旋锁保护一小段不能睡眠的队列操作。
condition-variable|条件変数|Condition Variable|条件变量|共有状態がある条件を満たすまで実行を待たせ、状態が変わったときに待機側へ通知する同期機構。|条件变量让线程等待共享状态变化，通常配合互斥锁并重新检查条件。|消费者在队列为空时等待，生产者放入任务后发出通知。
# 実メモリの利用
memory-allocation|メモリ割当て|Memory Allocation|内存分配|プログラムなどが使うための記憶領域を、空いている領域から確保する処理。|内存分配为程序或系统预留可使用的内存区域。|图像程序为加载的位图申请一段内存。
stack-memory|スタック領域|Call Stack Memory|调用栈内存|関数の呼出し順に従って戻り先や局所データなどを保存し、終了時に逆順で解放する記憶領域。|调用栈内存保存函数调用信息，每次返回时释放相应栈帧。|一个函数调用另一个函数时，新函数的调用记录加入栈顶。
heap-memory|ヒープ領域|Heap Memory|堆内存|関数の呼出し順とは独立に、必要な大きさの領域を実行時に確保するための記憶領域。|堆内存用于在运行期间分配具有不同大小和生命周期的数据。|创建需要在多个函数之间共享的对象时，可把它放在堆上。
memory-protection|メモリ保護|Memory Protection|内存保护|許可された領域以外への読出し、書込み、実行などを防止する機構。|内存保护限制程序可访问的地址以及允许的操作，避免应用互相破坏。|应用误写另一个进程的内存地址时，系统可以阻止它。
internal-fragmentation|内部断片化|Internal Fragmentation|内部碎片|割り当てた領域が要求より大きいため、割当て済み領域の内部に使われない空間が残ること。|内部碎片是已分配区域中因大小对齐等原因而闲置的空间。|程序只需 5 KiB，却分得 8 KiB，余下的 3 KiB 没有使用。
external-fragmentation|外部断片化|External Fragmentation|外部碎片|空き領域が小さな区画に分散し、合計容量は十分でも必要な連続領域を確保できないこと。|外部碎片指可用空间分散，单个连续区域可能不够大。|空闲内存总计 10 MB，若最大的连续块只有 2 MB，就无法直接分配连续的 4 MB。
memory-compaction|メモリコンパクション|Memory Compaction|内存紧缩|配置済みの領域を移動し、分散していた未使用領域をまとめて連続領域を作る処理。|内存紧缩通过移动可移动的数据，合并零散空间。|系统把可移动的内存页集中后，可获得一块较大的连续区域。
buffer|バッファ|Buffer|缓冲区|転送速度や処理のタイミングの違いを吸収するため、データを一時的にためる記憶領域。|缓冲区暂存数据，让不同速度的读写双方能平稳配合。|录音软件先把短时间内收到的音频样本存入缓冲区，再集中写盘。
double-buffering|二重バッファリング|Double Buffering|双缓冲|二つの一時記憶領域を交互に使い、一方の処理中にもう一方の内容を準備する方式。|双缓冲使用两块空间轮流准备和使用数据。|游戏显示当前帧时，先在另一块缓冲区绘制下一帧，再交换。
# 仮想記憶とページ
virtual-memory|仮想記憶|Virtual Memory|虚拟内存|プログラムが使うアドレスと実際の記憶場所を対応付け、独立したアドレス空間を提供する機構。|虚拟内存通过地址映射让进程看到自己的内存空间，也可按需加载部分内容。|两个进程可各自使用同一个虚拟地址而实际指向不同物理页。
virtual-address|仮想アドレス|Virtual Address|虚拟地址|プログラムから見える記憶位置で、実際の主記憶位置とは変換によって対応する値。|虚拟地址是程序用来引用内存位置的地址，需要转换或检查后才能访问物理内存。|进程读取某个指针时，硬件依据页表进行地址转换。
physical-address|物理アドレス|Physical Address|物理地址|変換の結果として、実際の主記憶上の位置などを指し示すアドレス。|物理地址标识硬件可寻址的实际位置，常用于指向主内存。|CPU 完成地址转换后，用物理地址访问对应的内存内容。
page|ページ|Page|页|固定長に分割した仮想アドレス空間の区画で、対応する実記憶の枠に配置される単位。|页是虚拟地址空间的固定大小单位，可以映射到物理页框。|系统可以为一个虚拟页建立到某个 4 KiB 物理页框的映射。
page-frame|ページフレーム|Page Frame|页框|物理的な主記憶を固定長に区切った区画で、仮想側の区画を収める単位。|页框是主内存中与虚拟页大小相匹配的固定区域。|装入虚拟页时，系统可选一个空闲页框容纳数据。
page-table|ページテーブル|Page Table|页表|仮想側の各区画がどの物理記憶領域に対応するかなどを記録した表。|页表记录虚拟页对应的物理页框，还可保存访问权限和有效状态。|硬件查页表确定虚拟地址对应的物理位置。
tlb|アドレス変換バッファ（TLB）|Translation Lookaside Buffer|地址转换缓存|最近使ったアドレス変換結果を保持し、対応表をたどる回数を減らす機構。|TLB 缓存近期使用的虚拟地址映射，减少重复查询页表的开销。|连续访问同一内存页上的数据时，可复用 TLB 里的映射。
page-fault|ページフォールト|Page Fault|页故障|参照先の区画が主記憶にない場合やアクセス条件を満たさない場合に発生する例外。|访问未映射页或违反访问权限时可能触发页故障，系统会根据原因处理。|首次访问按需加载的程序页时，系统接到页故障后将它载入。
thrashing|スラッシング|Thrashing|内存颠簸|主記憶に必要な区画が十分に収まらず、区画の入替えが頻発して処理がほとんど進まない現象。|内存颠簸指系统频繁换页，实际执行进展很小。|同时运行的程序耗尽可用内存后，系统频繁读写换页区，界面变得很慢。
# ファイルの指定と属性
file|ファイル|File|文件|データのまとまりを、OSが名前や属性とともに保存し、利用できるようにした単位。|文件是操作系统管理的一组数据，通常具有名称和属性。|将编辑中的说明保存成一个文本文件。
directory|ディレクトリ|Directory|目录|名前と対応する項目を管理し、データや下位の分類を階層的に整理する仕組み。|目录记录文件或子目录等条目，用于按层级组织数据。|把合同和发票分别放入两个目录。
root-directory|ルートディレクトリ|Root Directory|根目录|階層的なファイル管理構造の一番上にあり、上位を持たないディレクトリ。|根目录是文件目录树的起点。|在 Linux 中，用路径 / 表示根目录。
current-directory|カレントディレクトリ|Current Working Directory|当前工作目录|相対的な場所の指定を解釈するとき、既定の起点となるディレクトリ。|当前工作目录是进程解析普通相对路径时使用的基准位置。|在项目目录执行命令时，输入 README.md 可指向该目录下的文件。
absolute-path|絶対パス|Absolute Path|绝对路径|階層の起点を明示して、現在の作業場所に依存せずファイルなどを指定する記述。|绝对路径从文件系统的根等固定位置出发，不依赖当前目录。|从不同目录访问 /etc/hosts，指向的仍是同一个位置。
relative-path|相対パス|Relative Path|相对路径|現在の作業場所など、別に与えられる基準点を起点としてファイルなどを指定する記述。|相对路径以某个基准为起点，改变基准就可能指向别处。|images/logo.png 可表示当前目录下 images 目录中的文件。
extension|拡張子|Filename Extension|文件扩展名|一般にファイル名の最後のピリオドより後に置かれ、内容の種類を示す部分。|扩展名常用来提示文件类型，但文件内容仍需由程序实际解析。|photo.png 中的 png 提示这是一个 PNG 图像文件。
file-permissions|ファイルアクセス権|File Permissions|文件访问权限|利用者やグループに対して、ファイルの読出し、変更、実行などを認める範囲。|文件访问权限决定哪些用户可以读、写或执行文件。|把共享脚本设为团队成员可读、只有管理员可修改。
file-descriptor|ファイルディスクリプタ|File Descriptor|文件描述符|開いているファイルや入出力先を、実行中のプログラムが操作するために用いる番号。|在类 Unix 系统中，文件描述符是进程引用已打开资源的整数编号。|程序打开配置文件后，用返回的描述符读取其内容。
# ファイルシステムの仕組み
filesystem|ファイルシステム|File System|文件系统|記憶媒体などの上で、データを名前付きの項目として配置し、読出しや更新を管理する仕組み。|文件系统规定文件和目录怎样组织、定位及更新。|格式化 U 盘时，可以为它创建 exFAT 文件系统。
partition|パーティション|Disk Partition|磁盘分区|一つの記憶装置を、別々に利用できる論理的な領域に区切ったもの。|磁盘分区把同一设备划成多个可以独立使用的区域。|一块 SSD 可分出系统分区和个人数据分区。
mount|マウント|Mounting|挂载|ある記憶媒体などのファイル管理構造を、OSから参照できる場所に結び付ける操作。|挂载把文件系统接入操作系统可访问的位置。|在 Linux 中，把 U 盘的文件系统挂载到 /mnt/usb 后浏览其内容。
formatting|論理フォーマット|Logical Formatting|逻辑格式化|領域に管理用の構造を作り、新しいファイルシステムとして使えるようにする操作。|逻辑格式化在设备或分区上建立文件系统的管理结构。|使用新 U 盘前，在目标分区创建文件系统。
inode|iノード|Index Node|索引节点|UNIX系のファイルシステムなどで、属性やデータの位置を保持し、通常は名前を保持しない管理情報。|索引节点保存权限、时间和数据位置等元数据，名称通常由目录条目保存。|多个硬链接可以通过各自的名称指向同一个索引节点。
hard-link|ハードリンク|Hard Link|硬链接|既存の項目と同じ管理情報を直接参照する、別のディレクトリエントリ。|硬链接让不同名称引用同一文件对象，删除其中一个名称通常不会删除其他名称对应的数据。|给同一份文档建立硬链接后，从任一名称编辑都会修改同一文件。
symbolic-link|シンボリックリンク|Symbolic Link|符号链接|別のファイルなどの位置を示すパスを内容として持ち、参照時にその場所へ導く項目。|符号链接保存目标路径，访问时跳到该路径指向的位置。|创建名为 current 的符号链接，指向当前使用的版本目录。
journaling|ジャーナリング|Journaling|日志式记录|更新の予定などを記録し、障害後に記録を使って管理構造の整合性を回復できる方式。|日志式文件系统把相关变更记入日志，重启后可利用它恢复一致状态。|断电后，系统重放日志，恢复未完成更新涉及的文件系统结构。
defragmentation|デフラグメンテーション|Defragmentation|磁盘碎片整理|記憶装置上でばらばらに置かれたファイルの領域を、より連続した配置に整理する処理。|碎片整理重排文件占用位置，减少机械硬盘读取时的寻道。|整理老机械硬盘上长期反复修改的大文件，让其数据位置更连续。
# OSの構成とインタフェース
operating-system|オペレーティングシステム（OS）|Operating System|操作系统|ハードウェア資源を管理し、アプリケーションに実行や入出力の共通機能を提供する基盤ソフトウェア。|操作系统统一管理处理器、内存、设备和文件，为应用提供运行环境。|在电脑上安装操作系统后，应用可通过它打开文件和接收键盘输入。
kernel|カーネル|Kernel|内核|資源の割当てや入出力の制御など、OSの中心的な機能を担う部分。|内核是操作系统的核心，负责进程、内存和设备访问等关键工作。|应用请求读取文件时，内核协调文件系统和存储设备。
user-mode|ユーザモード|User Mode|用户态|特権命令や一部の記憶領域を直接使えない、アプリケーション向けの実行状態。|用户态限制普通程序直接执行高权限操作，需要通过系统接口申请服务。|文字编辑器在用户态运行，读取文件时调用操作系统。
kernel-mode|カーネルモード|Kernel Mode|内核态|OSの中核が、保護された記憶領域の利用や特権命令の実行を行える状態。|内核态允许执行系统管理所需的高权限操作。|内核在处理进程切换时可配置受保护的地址转换设置。
system-call|システムコール|System Call|系统调用|アプリケーションがOSの中核に、ファイル操作などの機能を正式に要求する仕組み。|系统调用是用户程序请求内核服务的接口。|应用请求打开文件时，可通过系统调用让内核检查权限并返回描述符。
shell|シェル|Shell|命令解释器|利用者が入力した命令を解釈し、プログラムの起動や入出力の接続などを行うソフトウェア。|Shell 接收命令并解释参数，可启动程序、组合命令或控制输入输出。|在终端输入命令后，由 Shell 启动对应程序。
cli|コマンドラインインタフェース（CLI）|Command-Line Interface|命令行界面|文字列で命令や引数を入力し、処理結果などを受け取る操作方式。|命令行界面通过文本命令操作软件，方便脚本化和远程使用。|管理员输入一行命令查看磁盘剩余空间。
gui|グラフィカルユーザインタフェース（GUI）|Graphical User Interface|图形用户界面|ウィンドウ、アイコン、ボタンなどの画面要素を使って操作する方式。|图形界面以可见的控件呈现操作，可用鼠标或触屏选择。|用户拖动文件图标，将文件移动到另一个文件夹。
rtos|リアルタイムOS（RTOS）|Real-Time Operating System|实时操作系统|定められた時間制約を守って処理できるよう、応答時間の予測可能性を重視したOS。|实时操作系统重视响应时间可预测，使关键任务能在规定时限内运行。|工业控制器按固定周期采集数据并调整电机输出。
# 起動と入出力の制御
firmware|ファームウェア|Firmware|固件|装置内の不揮発性メモリなどに保存され、装置の基本動作を制御するソフトウェア。|固件为设备提供贴近硬件的基础控制功能，部分固件可更新。|打印机固件控制进纸，并处理打印指令。
bios|BIOS|Basic Input/Output System|基本输入输出系统|従来型のPCで、電源投入時に装置を初期化して起動用プログラムを読み出すファームウェア。|传统 PC 的 BIOS 在启动时初始化硬件，再交给后续引导程序。|旧电脑的 BIOS 可按设定的启动顺序尝试从硬盘启动。
uefi|UEFI|Unified Extensible Firmware Interface|统一可扩展固件接口|従来のBIOSに代わるものとして広く使われ、ファームウェアとOS起動処理の接続を定める仕様。|UEFI 规定固件和操作系统引导程序之间的接口，常用于现代 PC。|现代电脑可从 EFI 系统分区加载操作系统引导程序。
bootloader|ブートローダ|Bootloader|引导加载程序|起動の途中で実行され、OSの中核などを記憶装置から主記憶へ読み込んで制御を渡すプログラム。|引导加载程序准备加载操作系统并把执行权交给它。|在双系统电脑中，引导加载程序可以显示操作系统选择菜单。
post|電源投入時自己診断（POST）|Power-On Self-Test|加电自检|電源を入れた直後に、起動に必要な主要部品が動作するかを検査する処理。|加电自检是在开机阶段检查内存等主要部件的过程。|内存未装牢时，开机自检可能通过指示灯报告故障。
device-driver|デバイスドライバ|Device Driver|设备驱动程序|OSからの共通の要求を、特定の機器が理解する制御に変換して入出力を行うソフトウェア。|设备驱动程序负责操作特定硬件，使系统和应用可通过统一接口使用设备。|安装打印机驱动后，应用可以把打印任务交给该机型处理。
interrupt|割込み|Interrupt|中断|入出力完了などの事象を通知して、プロセッサに通常の処理を中断し対応処理を行わせる仕組み。|中断使处理器能及时处理设备通知等事件，完成后可继续原来的执行。|网卡收到数据后，可以发出中断通知系统。
polling|ポーリング|Polling|轮询|入出力機器などの状態を、処理側が一定の間隔などで繰り返し問い合わせる方式。|轮询是主动反复查询状态，以发现设备或任务是否有新变化。|程序每隔一段时间检查传感器是否有新读数。
dma|直接メモリアクセス（DMA）|Direct Memory Access|直接内存访问|入出力装置と主記憶の間で、プロセッサがデータを一つずつ移さずに転送する方式。|DMA 让设备或控制器直接与内存传送数据，减轻 CPU 逐项复制的工作。|存储控制器可把一批读出的数据直接传送到内存缓冲区。
# 実行環境の入出力と管理
environment-variable|環境変数|Environment Variable|环境变量|実行環境が名前と値の組を提供し、プログラムが設定などを参照するために使う情報。|环境变量是进程可读取的键值配置，启动子进程时通常可传递给子进程。|将常用命令目录加入 PATH 环境变量后，Shell 能按名称找到命令。
standard-input|標準入力|Standard Input|标准输入|プログラムが既定の入力先として受け取るストリームで、通常は端末などに接続されるもの。|标准输入是程序读取输入的默认数据流，可接键盘、文件或另一个程序。|排序命令可以从标准输入读入一列文本。
standard-output|標準出力|Standard Output|标准输出|プログラムが通常の処理結果を送る既定のストリーム。|标准输出是程序写入正常结果的默认数据流，默认可显示在终端。|把目录列表命令的标准输出保存到文本文件。
standard-error|標準エラー出力|Standard Error|标准错误输出|通常の結果とは区別して、診断やエラーの情報を送る既定のストリーム。|标准错误输出独立于标准输出，适合传送错误和诊断信息。|把查询结果重定向到文件时，错误提示仍可保留在终端。
pipe|パイプ|Pipe|管道|あるプログラムの出力を、別のプログラムの入力へ受け渡す通信の仕組み。|管道连接程序的数据流，让输出可以直接交给下一程序继续处理。|把文件列表命令的输出传给计数命令。
redirection|リダイレクト|I/O Redirection|输入输出重定向|通常の入出力先を、ファイルなど別の入出力先へ切り替える操作。|输入输出重定向让命令改从指定来源读取，或把结果写到指定位置。|让备份命令把错误消息写入单独的日志文件。
daemon|デーモン|Daemon|守护进程|対話操作とは独立してバックグラウンドで動き、継続的に機能を提供するプログラム。|类 Unix 系统的守护进程在后台提供持续服务。|计划任务守护进程会在预定时间触发日常作业。
shell-script|シェルスクリプト|Shell Script|Shell 脚本|コマンドと実行順序などをファイルに記述し、コマンド解釈プログラムで実行するもの。|Shell 脚本把命令及执行顺序写入文件，适合自动化重复操作。|把查找日志和按日期归档的命令写进脚本，再每天定时运行。
