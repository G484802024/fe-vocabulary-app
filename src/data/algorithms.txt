# アルゴリズムの表現
algorithm|アルゴリズム|Algorithm|算法|ある問題を解くために、実行順や条件を明確にした有限の手順。|算法是一组明确、可按顺序执行并能结束的步骤，用来解决一类问题。|先检查购物车有无商品，再汇总金额，最后应用折扣。
flowchart|流れ図（フローチャート）|Flowchart|流程图|処理や判断を図形で表し、矢印で進行の向きを示す図。|流程图用不同图形表示处理、判断等步骤，并用箭头连接。|画出取款机从读卡到给出现金的处理流程。
pseudocode|擬似コード|Pseudocode|伪代码|特定の言語の細かい文法に従わず、処理手順をコードの形に近い記法で表したもの。|伪代码用接近程序的写法说明步骤，可以省略具体语言的语法细节。|先写出判断及格的步骤，再用 Java 实现。
sequence|順次構造|Sequential Control|顺序结构|複数の処理を、記述した順番に一つずつ実行する制御構造。|顺序结构按规定次序逐步执行各项操作。|读入单价和数量后，计算总价并显示结果。
selection-control|選択構造|Selection Control|分支结构|条件の成立の有無などによって、次に行う処理を切り替える制御構造。|分支结构根据条件结果决定接下来执行哪一段。|余额足够时支付，余额不足时提示充值。
iteration|反復構造|Iteration|循环结构|定めた回数や条件に従って、同じ処理を繰り返す制御構造。|循环结构按次数或条件反复执行同一段步骤。|依次处理购物车中的每一件商品。
recursion|再帰|Recursion|递归|問題を小さい同種の問題に置き換え、処理の中で同じ処理を呼び出す方法。|递归通过调用自身来解决规模更小的同类问题，需要适当的终止条件。|遍历一个文件夹时，用相同方法处理其中每个子文件夹。
base-case|基底条件|Base Case|递归基例|処理が自分自身をそれ以上呼び出さず、結果を直接返せる条件。|递归基例指出何时可以直接得到结果，从而终止递归。|统计目录中文件数时，空目录直接返回零。
# 計算量の基本
time-complexity|時間計算量|Time Complexity|时间复杂度|入力の規模が増えたときに、処理に要する操作の回数などがどう増えるかを表す指標。|时间复杂度描述输入变大时操作次数的增长趋势。|比较逐项查找与折半查找在数据扩大时的比较次数。
space-complexity|空間計算量|Space Complexity|空间复杂度|入力の規模が増えたときに、処理が使う記憶領域がどう増えるかを表す指標。|空间复杂度描述算法所占空间随输入规模如何增长。|比较复制整个列表和仅用一个临时变量时的空间需求。
big-o|O記法|Big O Notation|大 O 表示法|入力規模が大きくなったときの増え方について、定数倍などを除いて上限を表す記法。|大 O 给出增长率的渐近上界，忽略固定倍数和较低阶的项。|用 O(n²) 表示两层遍历的操作次数上界。
worst-case|最悪計算量|Worst-case Complexity|最坏情况复杂度|同じ入力規模で、最も多くの資源を使う入力を想定した計算量。|最坏情况复杂度关注固定输入规模下最费时或最费空间的情形。|在逐项查找中，目标不在列表里时需要检查所有元素。
average-case|平均計算量|Average-case Complexity|平均情况复杂度|各入力の出現確率を仮定して、必要な資源量の期待値で表す計算量。|平均情况复杂度依据假设的输入分布计算平均资源消耗。|假设目标在各位置等可能，估计顺序查找的平均比较次数。
constant-time|定数時間|Constant Time|常数时间|入力の大きさが増えても、必要な操作回数に一定の上限がある実行時間の性質。|常数时间指操作数的上界不随输入规模增加。|根据已知下标直接访问数组中的某项。
linear-time|線形時間|Linear Time|线性时间|代表的な操作回数が、入力の大きさと同じ割合で増える実行時間の性質。|线性时间指操作次数大体随输入规模成比例增长。|把清单中的所有数值各加一次得到总和。
logarithmic-time|対数時間|Logarithmic Time|对数时间|入力の大きさを一定の倍率で増やしても、代表的な操作回数が一定量ずつしか増えない性質。|对数时间的操作次数增长缓慢，输入规模每乘以一个固定倍数，操作次数大致只增加固定量。|对已排序的清单执行折半查找时，清单长度翻倍大约多检查一次。
# 解法の考え方
brute-force|総当たり法|Brute Force Search|穷举法|考えられる候補をすべて調べて、条件に合うものを見つける方法。|穷举逐个检查候选答案，适合规模较小且容易枚举的情形。|从几个可用时段中列出全部搭配，找出没有冲突的安排。
divide-and-conquer|分割統治法|Divide and Conquer|分治法|問題を小さな部分問題に分けて解き、その結果を組み合わせて全体の解を得る方法。|分治把大问题拆成小问题，分别解决后合并结果。|归并排序先分别排好前半和后半，再合并。
greedy|貪欲法|Greedy Algorithm|贪心算法|各段階でその時点の評価が最も良い選択を行い、解を組み立てる方法。|贪心法每一步按局部规则选择，能否得到整体最优解取决于问题。|安排尽可能多的不重叠会议时，优先选最早结束的会议。
dynamic-programming|動的計画法|Dynamic Programming|动态规划|同じ部分問題を何度も解かなくて済むよう、その解を保存して組み合わせる方法。|动态规划保存并复用子问题答案，避免重复计算。|保存到每个站点的最低费用，用来计算后续站点的最低费用。
memoization|メモ化|Memoization|记忆化|同じ引数で再度呼び出されたときに再計算を省けるよう、関数の計算結果を保存すること。|记忆化保存特定输入的计算结果，下次遇到同一输入时直接复用。|递归计算数列时缓存已经求出的项。
backtracking|バックトラック法|Backtracking|回溯法|候補を一段ずつ組み立て、途中で条件を満たせないと分かれば選択を取り消して別の候補を試す方法。|回溯逐步尝试选择，发现当前路线行不通时退回上一步再试。|填数独时遇到冲突，撤回最近一次填写并尝试其他数字。
branch-and-bound|分枝限定法|Branch and Bound|分支限界法|候補を枝に分け、現在の最良解より良い結果が得られないと見積もれる枝を省く方法。|分支限界用界估计某个分支可能达到的最好结果，跳过无法改善当前答案的分支。|排送货路线时，跳过估计费用已超过最佳方案的路线分支。
heuristic|発見的手法（ヒューリスティック）|Heuristic|启发式方法|厳密な最適性の保証よりも、経験則などを使って実用的な解を得ることを重視する方法。|启发式利用经验规则更快找到可用结果。|临时安排巡检时，优先选离当前位置最近的未巡检点。
# 探索と照合
linear-search|線形探索|Linear Search|顺序查找|候補を先頭などから一つずつ確認し、目的の値を探す方法。|顺序查找逐项比较，可以用于未排序的列表。|在一份未排序的报名表中逐行查找姓名。
binary-search|二分探索|Binary Search|二分查找|整列済みの範囲の中央を調べ、探す範囲を半分ずつに絞る方法。|二分查找利用已有的顺序，每次比较中间项并排除大约一半候选。|在按编号排序的学生名单中查找一个学号。
lower-bound|下限探索（lower bound）|Lower Bound Search|查找下界|昇順に並ぶ列から、指定値以上の値が初めて現れる位置を探す方法。|下界查找定位第一个大于等于目标值的位置。|从按日期排序的预约中找到当天及以后最早的一条。
upper-bound|上限探索（upper bound）|Upper Bound Search|查找上界|昇順に並ぶ列から、指定値を超える値が初めて現れる位置を探す方法。|上界查找定位第一个严格大于目标值的位置。|在升序成绩单里找到第一位分数超过 60 分的学生。
sentinel-search|番兵法による探索|Sentinel Search|哨兵查找|目的の値を探索範囲の末尾の後ろに置き、繰返し中の範囲確認を省く方法。|哨兵查找临时在末尾加上目标值，使循环必然能遇到它，再判断找到的位置是否属于原范围。|在有额外空位的编号表中，用哨兵减少查找循环里的边界判断。
naive-matching|単純文字列照合|Naive String Matching|朴素字符串匹配|本文中の各開始位置で、パターンの文字を最初から比較して一致を探す方法。|朴素匹配把搜索词放到正文的每个候选起点逐字符比较。|在较短的留言里逐个位置查找“考试”。
kmp|KMP法|Knuth–Morris–Pratt Algorithm|KMP 字符串匹配|パターンの接頭部と接尾部の一致情報を利用し、照合済みの本文を戻らずに検索する方法。|KMP 预先计算模式串的前后缀信息，匹配失败时保留可复用的部分。|在大量由重复字母组成的文本里快速寻找固定字符串。
interpolation-search|補間探索|Interpolation Search|插值查找|整列した数値列の両端の値と目的値の比から、次に調べる位置を推定する方法。|插值查找根据目标值在当前数值范围内的比例估计位置，适合数值分布较均匀的有序列表。|在编号大致均匀递增的清单中，根据目标编号估计从哪一项开始比较。
# 整列アルゴリズム
bubble-sort|バブルソート|Bubble Sort|冒泡排序|隣り合う要素を比べ、順序が逆なら交換する走査を繰り返す整列法。|冒泡排序反复交换相邻的逆序项，让一端逐步有序。|对几张写有分数的卡片练习相邻换位。
selection-sort|選択ソート|Selection Sort|选择排序|未整列の範囲から最小値などを選び、順に所定の位置へ置く整列法。|选择排序每轮从未排序部分找出最小项或最大项，放到该去的位置。|从一堆卡片不断选出编号最小的一张，按顺序摆放。
insertion-sort|挿入ソート|Insertion Sort|插入排序|次の要素を、既に並んでいる部分の適切な位置に差し込む整列法。|插入排序逐项将新元素插入已有序的部分。|打牌时把新摸到的牌放进手牌的正确位置。
merge-sort|マージソート|Merge Sort|归并排序|要素列を分割し、整列した部分列を併合して全体を整列する方法。|归并排序将数据拆开排序，再把有序部分合并。|分别排好两个班的成绩后，合并成按分数排列的年级名单。
quick-sort|クイックソート|Quicksort|快速排序|基準値を選んで要素を大小に分け、その部分に対して同じ処理を繰り返す整列法。|快速排序围绕基准值划分数据，再递归排序各部分。|选一个产品价格为基准，把待排序商品分成较低价和较高价两组。
heap-sort|ヒープソート|Heapsort|堆排序|最大値または最小値を素早く取り出せる木構造を作り、根の値を順に確定する整列法。|堆排序先建堆，再不断取出堆顶，按顺序确定各元素。|从最大堆依次取出最高分，得到从高到低的成绩序列。
counting-sort|計数ソート|Counting Sort|计数排序|限られた範囲の整数について、値ごとの出現回数を数えて整列する方法。|计数排序统计每个值出现几次，根据计数确定排序位置。|给 0 到 100 分的成绩排序时，先统计每个分数的人数。
radix-sort|基数ソート|Radix Sort|基数排序|桁ごとの値を順に処理して、全体の順序を作る整列法。|基数排序按数字或字符的各位逐步分组排序。|对固定六位的编号从个位开始逐位排序，每轮保留同一位上的原顺序。
stable-sort|安定なソート|Stable Sort|稳定排序|比較に使うキーが等しい要素どうしの、整列前の順序を保つ整列。|稳定排序会保留相同键值的记录在排序前的相对顺序。|按部门稳定排序时，同一部门的员工仍按原来的入职顺序排列。
in-place-sort|インプレースソート|In-place Sort|原地排序|入力全体の複製を別に作らず、主に元の領域の中で要素を移動する整列。|原地排序主要在输入原本占用的空间中重排，所需额外存储很小。|直接在原数组中交换元素来排序，而非另建同样大小的数组。
# 線形データ構造
array|配列|Array|数组|添字で位置を指定して要素を取り出せる、順序付きの格納構造。|数组按位置组织元素，可用下标直接取出指定元素。|用下标 0 到 6 保存并访问一周七天的客流量。
dynamic-array|動的配列|Dynamic Array|动态数组|要素数が容量を超えると領域を確保し直すなどして、格納容量を増やせる配列。|动态数组能在需要时扩大底层空间，同时保留下标访问能力。|不断向联系人清单添加姓名，程序在空间不足时自动扩容。
linked-list|連結リスト|Linked List|链表|各要素が他の要素への参照を持ち、その参照をたどって順番にアクセスする構造。|链表通过节点间的引用维持顺序。|修改播放列表中相邻项目的引用以插入一首歌曲。
singly-linked-list|単方向リスト|Singly Linked List|单向链表|各要素が次の要素を指し、一方向にだけたどれる連結構造。|单向链表的节点只有后继引用，从当前位置通常只能向后遍历。|用节点的 next 引用按加入顺序读取任务。
doubly-linked-list|双方向リスト|Doubly Linked List|双向链表|各要素が直前と直後の両方を指し、前後のどちらにもたどれる連結構造。|双向链表为每个节点保存前驱和后继引用。|图片查看器可以从当前图片切换到上一张或下一张。
stack|スタック|Stack|栈|最後に入れた要素を最初に取り出す構造。|栈按后进先出顺序访问元素。|撤销编辑时先撤销最近一次修改。
queue|キュー|Queue|队列|最初に入れた要素を最初に取り出す構造。|队列按先进先出顺序处理元素。|打印任务按提交先后排队。
deque|両端キュー|Double-ended Queue|双端队列|列の先頭と末尾のどちらからでも要素を追加し、取り出せる構造。|双端队列支持在两头插入和删除元素。|任务池可在尾部加入普通任务，在头部加入优先处理的任务。
priority-queue|優先度付きキュー|Priority Queue|优先队列|追加された順に関係なく、設定された優先度に従って要素を取り出す構造。|优先队列按优先级提供下一项，先加入的元素不一定先处理。|客服系统先分配紧急工单。
circular-buffer|リングバッファ|Circular Buffer|环形缓冲区|固定長の領域で、書込み位置や読取り位置が末尾に達したら先頭に戻る構造。|环形缓冲区让读写位置循环利用一块固定空间。|在固定内存中保存最近收到的一段传感器样本。
# 木構造
tree|木構造|Tree|树|一つの根から親子関係をたどって節点を階層的に表せる構造。|树用层级关系组织节点。对有根树来说，根之外的节点各有一个父节点。|用树表示公司总部、部门和小组之间的隶属关系。
root|根（ルート）|Root Node|根节点|親を持たず、階層の起点となる節点。|根节点是有根树的起点，没有父节点。|网站栏目结构中，最上层的首页可作为根节点。
leaf|葉（リーフ）|Leaf Node|叶节点|子を一つも持たない末端の節点。|叶节点是没有子节点的树节点。|产品分类最末层的“无线鼠标”栏目没有子栏目，可视为叶节点。
tree-depth|節点の深さ|Node Depth|节点深度|根から特定の節点までに通る辺の数。|节点深度是在有根树中从根到该节点经过的边数。|根目录的直接子目录深度为 1。
tree-height|木の高さ|Tree Height|树的高度|根から最も遠い葉までに通る辺の数。|按边数定义，树的高度等于树中最大节点深度。|目录树最深有四层子目录时，高度为 4。
binary-tree|二分木|Binary Tree|二叉树|各節点が持つ子を最大二つに限り、左と右を区別する木。|二叉树每个节点最多有两个子节点，左右位置有区别。|用二叉树表示每个问题只有两个分支的判断流程。
binary-search-tree|二分探索木|Binary Search Tree|二叉搜索树|各節点を基準として、小さいキーを左側、大きいキーを右側に配置する木。|二叉搜索树按节点键值划分左右子树，便于按键查找。|按产品编号插入节点后，根据目标编号决定向左还是向右找。
balanced-tree|平衡木|Balanced Tree|平衡树|探索が極端に長くならないよう、枝の高さなどに制約を設ける木。|平衡树通过约束树形，控制增删节点后的高度。|持续按编号插入数据时，自动调整结构以免所有节点偏到同一侧。
heap|ヒープ|Heap|堆|親子の間に一定の大小関係があり、根から最大値か最小値を取り出せる構造。|堆维护父子节点间的大小关系，使最小值或最大值位于堆顶。|用最小堆快速找到最早应执行的定时任务。
trie|トライ木|Trie|字典树|文字列の先頭から共通する部分を同じ経路で表す木。|字典树共享字符串的相同前缀，便于查找前缀对应的词。|输入“com”后列出 computer 和 compile 等候选。
# グラフの表現
graph|グラフ|Graph|图|複数の対象と対象どうしの結び付きを、頂点と辺で表す構造。|图以顶点和边来表示对象及其连接关系。|用车站表示顶点，用相邻站之间的线路表示边。
vertex|頂点|Vertex|顶点|グラフで、他の対象とつながり得る個々の対象。|顶点是图中参与连接的对象。|在社交图中，每位用户对应一个顶点。
edge|辺|Edge|边|グラフで、二つの頂点の間のつながりを表す要素。|边用来表达图中两个顶点之间的连接。|在道路图中，一条公路可以用连接两座城镇的边来表示。
directed-graph|有向グラフ|Directed Graph|有向图|各辺について、始点から終点へ向かう向きを区別するグラフ。|有向图的边有方向，从甲到乙并不自动意味着从乙到甲。|用箭头记录各网页链接指向的页面。
undirected-graph|無向グラフ|Undirected Graph|无向图|辺の両端について、出発側と到着側の区別を設けないグラフ。|无向图的边只表示两端相连，不区分方向。|用无向边连接可双向通行的道路两端。
weighted-graph|重み付きグラフ|Weighted Graph|带权图|辺に距離や費用などの値を対応させたグラフ。|带权图为边分配数值，可表示距离、耗时或费用。|按公里数给道路图上的每条边设权重。
adjacency-list|隣接リスト|Adjacency List|邻接表|頂点ごとに、辺で直接つながる相手を列挙する表現方法。|邻接表为每个顶点列出与它直接相连的顶点。|对每座车站保存能从该站直达的下一站。
adjacency-matrix|隣接行列|Adjacency Matrix|邻接矩阵|頂点の組ごとの接続の有無などを、二次元の表で表現する方法。|邻接矩阵用二维表保存每对顶点是否连接或相应权值。|在站点表的第 2 行第 3 列填 1，表示站点 2 可直达站点 3。
dag|有向非巡回グラフ（DAG）|Directed Acyclic Graph|有向无环图|辺の向きに従って進んだとき、どの頂点からも一周して元に戻れないグラフ。|有向无环图的边有方向，并且没有可以沿方向返回原点的环。|用它表示各作业的先后依赖，避免任务互相等待对方先完成。
# グラフと木の走査
bfs|幅優先探索（BFS）|Breadth-first Search|广度优先搜索|開始点に近い階層から順に、通常は待ち行列を使って訪問する方法。|广度优先搜索按距离起点的边数逐层访问，常用队列实现。|在每步代价相同的迷宫中找步数最少的出口。
dfs|深さ優先探索（DFS）|Depth-first Search|深度优先搜索|一つの経路を行けるところまで先にたどり、その後に戻って別の経路を調べる方法。|深度优先搜索先深入当前路径，再返回寻找未访问的分支。|遍历文件夹时，先读完当前子文件夹，再处理同层其他子文件夹。
preorder|先行順走査|Preorder Traversal|前序遍历|木の各節点で、子をたどる前にその節点自身を訪問する走査順。|前序遍历先访问当前节点，再访问它的子树。|显示目录清单时，先打印目录名，再打印目录内的文件。
inorder|中間順走査|Inorder Traversal|中序遍历|二分木で、左の部分木、節点自身、右の部分木の順に訪問する走査順。|中序遍历按左子树、当前节点、右子树访问。|中序遍历二叉搜索树可按键值升序列出节点。
postorder|後行順走査|Postorder Traversal|后序遍历|木の各節点で、すべての子をたどった後にその節点自身を訪問する走査順。|后序遍历先访问子树，最后访问父节点。|删除目录树时先清理子目录和文件，最后删除外层目录。
dijkstra|ダイクストラ法|Dijkstra's Algorithm|迪杰斯特拉算法|辺の重みが負でないグラフで、ある始点からの最短距離を順に確定する方法。|迪杰斯特拉算法在边权非负时，逐步确定从起点到各节点的最短距离。|按道路距离寻找从仓库到不同门店的最短路线。
topological-sort|トポロジカルソート|Topological Sort|拓扑排序|すべての有向辺が前から後ろを向くように、頂点を一列に並べる方法。|拓扑排序将有向无环图的节点排成一个符合所有依赖关系的次序。|按先修要求给一组课程安排学习顺序。
connected-component|連結成分|Connected Component|连通分量|無向グラフの中で、互いに経路で到達できる頂点を最大限まとめた集合。|连通分量是无向图中互相可达的一整组顶点。|道路受阻后，找出仍能相互通行的各组城镇。
# ハッシュによる格納
hash-table|ハッシュ表|Hash Table|哈希表|キーから計算した値を使って、キーと対応データを探す格納構造。|哈希表通过键计算位置，以便快速保存和查找键对应的数据。|用商品编号作为键，查找商品说明。
hash-function|ハッシュ関数|Hash Function|哈希函数|任意のキーを所定の範囲や長さの値へ変換する決定的な関数。|哈希函数将同一输入稳定地映射成同一范围内的值。|在哈希表中把字符串键映射为一个槽位编号。
hash-collision|ハッシュ衝突|Hash Collision|哈希冲突|異なるキーが計算の結果として同じ値や格納位置に対応すること。|哈希冲突指两个不同的键被映射到相同哈希值或表位置。|两个不同商品编号分到了同一个槽位，需要额外区分。
chaining|チェイン法|Separate Chaining|链地址法|同じ格納位置に対応した複数の要素を、その位置に関連付けた別の列などで保持する方式。|链地址法为每个槽位保存一个集合，容纳映射到同一槽位的多个键。|把哈希值落在同一个槽位的联系人放进该槽位的链表。
open-addressing|開番地法|Open Addressing|开放寻址法|対応する格納位置が使用中なら、同じ表の中で別の候補位置を順に調べる方式。|开放寻址将冲突元素存放到表内其他可用位置。|插入一个学号时，若首选位置已占用，就沿探查顺序寻找空位。
linear-probing|線形探査法|Linear Probing|线性探查法|候補位置が使用中のとき、隣の位置を順に調べ、表の末尾の次は先頭へ戻る方式。|线性探查在发生冲突时依次检查后续槽位，到表尾后从表头继续。|编号落在第 5 槽且已占用时，接着检查第 6 槽。
load-factor|負荷率（ハッシュ表）|Hash Table Load Factor|哈希表装载因子|格納されている要素数を、表の格納位置の数で割った指標。|装载因子反映平均每个槽位对应多少元素，常用于判断何时扩容。|表有 100 个槽位且存了 70 条记录，装载因子为 0.7。
rehashing|再ハッシュ|Rehashing|重新哈希|表の大きさなどを変えた後、既存のキーの格納位置を計算し直して配置する処理。|重新哈希根据更新后的表容量或映射方式，重算各元素的存放位置。|哈希表扩容后，把原有的联系人记录重新分配到新槽位。
