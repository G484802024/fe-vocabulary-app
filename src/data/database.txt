# 関係データベースの構成
db|データベース|Database|数据库|検索や更新をしやすくするために体系的に整理されたデータの集まり。|数据库按一定结构组织数据，便于保存、查找和更新。|图书馆把馆藏、读者和借阅记录集中存放。
dbms|データベース管理システム（DBMS）|Database Management System|数据库管理系统|データの定義、検索、更新、アクセス管理などを行うソフトウェア。|DBMS是管理数据库的软件，负责处理查询、更新和访问权限。|学校使用数据库管理系统登记学生选课。
rdb|関係データベース|Relational Database|关系数据库|データを行と列を持つ関係で表現し、関係演算で扱うデータベース。|关系数据库用表来组织数据，可以按条件组合不同表中的数据。|订单表用顾客编号关联顾客表。
table|表（テーブル）|Table|表|同じ構造を持つデータを行と列に整理した、関係データベースの単位。|表像一张有固定列的清单，每行记录一个对象或事件。|商品表记录每件商品的编号和价格。
tuple|行（タプル）|Tuple|行（元组）|関係の中で、各属性に対応する値を一組にしたもの。|一行给出一组属性值，通常表示一条记录。|学生表中的一行记录小王的编号、姓名和班级。
attribute|列（属性）|Attribute|列（属性）|関係の中で、各行が持つ特定の項目を表すもの。|属性说明每条记录要保存哪一类信息。|订单表中的下单日期列记录订单何时产生。
domain|ドメイン（定義域）|Domain|值域|ある属性に設定できる値の集合。|值域规定某个属性允许取哪些值。|借阅状态的值域可以是借出、归还和逾期。
null|NULL値|Null|空值|値が不明または該当しないことを表す、通常の値とは異なるしるし。|NULL表示缺少或不适用的数据，在 SQL 中要用 IS NULL 判断。|尚未归还的借阅记录把归还日期留为 NULL。
# キーと整合性
primary-key|主キー|Primary Key|主键|行を一意に識別するために表で一つ指定する、NULLを許さない列の組。|主键唯一标识每一行，可以由一列或多列组成，其组成列不得为空。|用学号作为学生表的主键。
foreign-key|外部キー|Foreign Key|外键|別の表または同じ表の参照先のキーに値を対応させる列の組。|外键把一条记录关联到另一条合法记录，用于约束引用关系。|借阅表的图书编号只能引用馆藏表里存在的编号。
candidate-key|候補キー|Candidate Key|候选键|行を一意に識別でき、どの列も省くことのできない列の組。|候选键既能唯一标识记录，又没有可以去掉的多余列。|如果学号和统一注册号都能分别唯一标识学生，两者都是候选键。
composite-key|複合キー|Composite Key|复合键|複数の列を組み合わせて一つのキーとして扱うもの。|复合键使用多个字段的组合来标识或引用记录。|用学生编号和课程编号组成选课表的复合主键。
surrogate-key|代理キー|Surrogate Key|代理键|業務上の意味を持たず、行を識別する目的で人工的に付与するキー。|代理键是人为分配的标识，通常用来让标识独立于业务内容。|系统分配顾客编号，顾客更改手机号时编号仍保持原值。
unique-constraint|一意性制約（UNIQUE）|Unique Constraint|唯一性约束|指定した列の組で、同じ値の組が重複することを制限する制約。|唯一性约束防止重复的取值组合。空值的具体规则因系统而异。|在账号表限制已登记的用户名不可重复。
not-null|非NULL制約（NOT NULL）|Not-null Constraint|非空约束|指定した列に、値が不明または存在しないことを示すしるしを格納できないようにする制約。|非空约束要求字段有值。空字符串能否存入则由其他规则决定。|订单的下单时间列设为非空。
check-constraint|検査制約（CHECK）|Check Constraint|检查约束|格納する値について、指定した条件式が偽となるデータを拒否する制約。|检查约束拒绝不符合条件的数据。在 SQL 中要另用非空约束拒绝 NULL。|给库存量添加大于等于零的检查。
# モデリングとスキーマ
er-model|E-Rモデル|Entity–Relationship Model|实体关系模型|対象となるものとその属性、および対象どうしの関連でデータを表現するモデル。|实体关系模型用实体、属性和联系描述业务数据。|用顾客、订单两个实体及其购买联系规划商店数据库。
entity|実体（エンティティ）|Entity|实体|データモデルで、他と区別して管理する対象。|实体是需要区分和管理的对象，可以是现实中的事物或事件。|每位顾客都是顾客实体的一条实例。
relationship|関連（リレーションシップ）|Relationship|联系|データモデルで、異なる実体や同じ種類の実体どうしの結び付き。|联系说明实体之间的关联方式。|员工与部门之间存在所属联系。
cardinality|多重度|Relationship Cardinality|联系基数|関連に参加する一方の実体に、他方の実体がいくつ対応し得るかを表すもの。|联系基数说明两个实体之间最多或最少能对应几条记录。|一张订单可以包含多条明细。
one-to-one|1対1の関連|One-to-one Relationship|一对一联系|どちらの実体から見ても、対応できる相手が最大一つである関連。|一对一表示任一侧的一条记录最多对应另一侧的一条。|每位员工最多有一个专用档案，每份档案只属于一位员工。
one-to-many|1対多の関連|One-to-many Relationship|一对多联系|一方の実体には相手が複数対応でき、相手からはその一方が最大一つ対応する関連。|一对多表示一端可关联多条记录，多端每条最多回到一个对象。|一个部门有多位员工，每位员工只归属一个部门。
many-to-many|多対多の関連|Many-to-many Relationship|多对多联系|関連のどちらの側から見ても、複数の相手が対応できる関連。|多对多表示双方各自都能关联对方的多条记录。|一名学生选多门课，一门课也可有多名学生。
schema|スキーマ|Schema|模式|データの構造や制約などを定義した設計情報。|模式描述数据库如何组织数据，包括表、列、类型和约束。|新建订单表之前，先在模式中定义订单编号的类型和主键。
# 正規化と関数従属性
normalization|正規化|Normalization|规范化|重複や更新時の不整合を減らすため、依存関係に基づいて表を整理すること。|规范化依据数据之间的依赖关系设计表，以减少重复和修改异常。|把反复出现在订单中的顾客资料提到独立的顾客表。
functional-dependency|関数従属性|Functional Dependency|函数依赖|ある属性の組の値が同じなら、別の属性の組の値も必ず同じになるという関係。|函数依赖表示给定一组属性，就能确定另一组属性。|在课程资料中，课程编号能确定课程名称。
partial-dependency|部分関数従属|Partial Functional Dependency|部分函数依赖|ある属性の値が、決定側の属性の組の一部だけで決まる状態。|部分依赖表示给定组合的一部分就足以确定某属性。|在选课明细中，只需课程编号就能确定课程名，无需学生编号。
transitive-dependency|推移的関数従属|Transitive Functional Dependency|传递函数依赖|ある属性が中間の属性によって決まり、その中間の属性が別の属性によって決まる関係。|传递依赖是经过中间属性形成的间接依赖。|学号决定班级号，班级号决定班主任，因此学号也能间接确定班主任。
first-normal-form|第1正規形|First Normal Form|第一范式|表の各項目が単一の値を持ち、繰り返し項目を含まない状態。|第一范式要求表中每个字段按设计只保存一个值。|把某读者的多次借阅分别记成多行。
second-normal-form|第2正規形|Second Normal Form|第二范式|第1正規形であり、非キー属性が候補キーの一部分だけに従属しない状態。|第二范式要求非主属性完全依赖每个候选键。|把只由课程编号决定的课程名称从选课表拆出。
third-normal-form|第3正規形|Third Normal Form|第三范式|非自明な関数従属の決定側がスーパーキーであるか、従属側が候補キーの構成属性である状態。|第三范式可用来消除常见的非主属性间接依赖。正式条件要求决定方是超键，或者被决定的属性属于某个候选键。|把由部门编号决定的部门名从员工表迁入部门表。
denormalization|非正規化|Denormalization|反规范化|検索性能などを考慮し、整理されたデータの一部を意図的に重複させる設計。|反规范化主动保留某些冗余数据以减少查询开销，同时要管理同步。|订单汇总表保存预先统计的金额，以减少每次打开页面的计算。
# 関係演算と結合
selection|選択|Selection|选择|関係から条件に一致する行を取り出す関係演算。|选择按条件筛选行，保留符合要求的记录。|从商品表中只提取库存大于零的行。
projection|射影|Projection|投影|関係から指定した属性だけを取り出す関係演算。|投影保留指定的属性。在纯关系代数中，结果中的重复元组会合并。|从学生表提取姓名和班级两列。
cartesian-product|直積|Cartesian Product|笛卡尔积|一方の関係の各行と、他方の関係の各行を総当たりで組み合わせる演算。|笛卡尔积为两张表的每一对行生成组合。|把每种颜色与每种尺码配对，列出全部商品款式。
inner-join|内部結合（INNER JOIN）|Inner Join|内连接|指定した結合条件が成り立つ行の組だけを返す結合。|内连接只输出满足连接条件的行对。|把订单和顾客按顾客编号连接，仅保留能找到顾客的订单。
left-join|左外部結合（LEFT JOIN）|Left Outer Join|左外连接|左側の行をすべて残し、対応する右側の行がなければ右側の列をNULLで補う結合。|左外连接保留左表的所有记录，并用 NULL 补齐未匹配的右表字段。|列出所有顾客及其订单，也保留还没买过东西的顾客。
full-join|完全外部結合（FULL OUTER JOIN）|Full Outer Join|全外连接|一致した行の組に加え、左側と右側それぞれの一致しなかった行も残す結合。|全外连接保留两边匹配的行，也分别保留两边未匹配的记录。|核对两个渠道的会员清单时同时看到各渠道独有的会员。
union|和集合（UNION）|Union|并集|同じ形式の二つの結果のうち、いずれかに含まれる行を重複なしで返す演算。|并集合并两个结果的行，并去除重复行。|合并春季和秋季的报名名单，每位报名人只出现一次。
intersection|積集合（INTERSECT）|Intersection|交集|同じ形式の二つの結果の両方に現れる行だけを返す演算。|交集提取两个集合共有的记录。|找出同时参加了线上和线下活动的会员。
set-difference|差集合（EXCEPT）|Set Difference|差集|一方の結果に現れ、他方の結果には現れない行を返す演算。|差集从第一个结果中排除第二个结果里出现的记录。|从报名名单中排除已签到的人，得到未签到名单。
# SQLによる抽出と集計
select|SELECT文|SELECT Statement|SELECT 查询语句|表などから式の値や行を取り出し、結果を返すSQLの文。|SELECT 查询数据或表达式的结果。|查询图书表的书名和作者。
where|WHERE句|WHERE Clause|WHERE 筛选子句|集約の前などに、条件を満たす行だけを対象にするSQLの句。|WHERE 对单条记录应用条件，通常在分组统计之前执行筛选。|只统计本月下单的订单。
group-by|GROUP BY句|GROUP BY Clause|GROUP BY 分组子句|指定した式の値ごとに行をまとめ、グループ単位で処理できるようにするSQLの句。|GROUP BY 按指定字段的取值分组，便于对每组分别统计。|按门店分组计算各店当天的营业额。
having|HAVING句|HAVING Clause|HAVING 分组筛选子句|グループ単位の条件を指定して、条件に合うグループを残すSQLの句。|HAVING 筛选分组后的结果，可以使用聚合值作为条件。|只显示订单数量达到一百笔的门店。
order-by|ORDER BY句|ORDER BY Clause|ORDER BY 排序子句|指定した式と順序に従って、結果の行を並べるSQLの句。|ORDER BY 按指定字段和升序或降序排列查询结果。|将图书按出版日期从新到旧显示。
distinct|DISTINCT指定|DISTINCT Quantifier|DISTINCT 去重|問い合わせ結果から同じ値の組を持つ行の重複を除く指定。|DISTINCT 让输出列的相同取值组合只保留一次。|查询学生表中出现过的班级名称，每班只显示一行。
subquery|副問合せ|Subquery|子查询|別のSQL文の内側に記述し、外側の処理に結果を渡す問合せ。|子查询嵌在另一条语句中，向外层提供行、列或单个值。|先算出平均单价，再查出高于平均价的商品。
view|ビュー|View|视图|問い合わせの定義を保存し、表のように参照できるようにしたもの。|普通视图保存查询定义，使用时可以像表一样查询它。|向客服提供仅显示订单编号和处理状态的视图。
# SQLの式と集約関数
count|COUNT関数|COUNT Aggregate Function|COUNT 计数函数|行の数、または式がNULLでない行の数を返す集約関数。|COUNT(*) 统计行数，COUNT(字段) 统计该字段具有非空值的行数。|用 COUNT(*) 统计今天的订单数。
sum|SUM関数|SUM Aggregate Function|SUM 求和函数|NULLを除いた数値の合計を返す集約関数。|SUM 对一组非空数值求和。|汇总各笔订单的金额，得到当天销售额。
avg|AVG関数|AVG Aggregate Function|AVG 平均值函数|NULLを除いた数値の算術平均を返す集約関数。|AVG 用有效数值计算算术平均值。|计算已录入成绩的学生的平均分。
min|MIN関数|MIN Aggregate Function|MIN 最小值函数|グループ内のNULLでない値のうち、順序が最も小さい値を返す集約関数。|MIN 返回一组非空值中排序最靠前的值。|找出某商品最早的一笔下单时间。
max|MAX関数|MAX Aggregate Function|MAX 最大值函数|グループ内のNULLでない値のうち、順序が最も大きい値を返す集約関数。|MAX 返回一组非空值中排序最靠后的值。|找出考试成绩表中的最高分。
coalesce|COALESCE式|COALESCE Expression|COALESCE 取首个非空值|指定した式を左から見て、最初に現れるNULL以外の値を返す式。|COALESCE 返回第一个非 NULL 的参数，参数全为空时返回 NULL。|显示顾客昵称，缺失时改用顾客姓名。
case|CASE式|CASE Expression|CASE 条件表达式|条件や値に応じて、複数の候補の中から返す値を選ぶSQLの式。|CASE 按条件返回不同结果。|将成绩按区间显示为合格或待补考。
like|LIKE述語|LIKE Predicate|LIKE 模式匹配谓词|ワイルドカードを含むパターンに、文字列が合うかを調べる述語。|LIKE 用通配符匹配文字，常用的百分号代表任意长度的字符序列。|查询书名以“数据”开头的图书。
# データの定義・更新
ddl|データ定義言語（DDL）|Data Definition Language|数据定义语言|表や制約などのデータベース構造を作成、変更、削除する命令の分類。|DDL 是创建或改变数据库结构的一类语句。|创建新表并定义主键属于 DDL 操作。
dml|データ操作言語（DML）|Data Manipulation Language|数据操作语言|データベース内の行の挿入や変更、削除などを行う命令の分類。|DML 用来操作数据库里的记录，例如新增、修改和删除。|为一位读者添加新的借阅记录。
insert|INSERT文|INSERT Statement|INSERT 插入语句|既存の表に一つ以上の行を追加するSQLの文。|INSERT 向现有表中加入一条或多条记录。|将新到的一本书登记到馆藏表。
update|UPDATE文|UPDATE Statement|UPDATE 更新语句|既存の行について、指定した列の値を書き換えるSQLの文。|UPDATE 修改已有行中的指定字段。|把已归还图书的归还日期写入借阅记录。
delete|DELETE文|DELETE Statement|DELETE 删除语句|条件に合う行を表から取り除くSQLの文。|DELETE 删除表中的记录，表结构仍然保留。|删除标记为已取消的临时预约记录。
create-table|CREATE TABLE文|CREATE TABLE Statement|CREATE TABLE 建表语句|列や制約を指定して、新しい表を定義するSQLの文。|CREATE TABLE 创建一张新表，并声明各列的类型和约束。|为新开的课程建立签到记录表。
alter-table|ALTER TABLE文|ALTER TABLE Statement|ALTER TABLE 改表语句|既にある表の列や制約など、その定義を変更するSQLの文。|ALTER TABLE 修改既有表的结构。|给顾客表增加一个电子邮箱列。
drop-table|DROP TABLE文|DROP TABLE Statement|DROP TABLE 删表语句|指定した表の定義を取り除き、その表を使えなくするSQLの文。|DROP TABLE 移除整张表的定义及其数据。|移除导入完成后废弃的临时表。
# トランザクション管理
transaction|トランザクション|Transaction|事务|一つの処理単位としてまとめて実行結果を確定または取消しする一連の操作。|事务把若干操作作为一个整体确认或撤销。|转账时把付款人扣款和收款人入账放在同一事务。
atomicity|原子性|Atomicity|原子性|一連の処理がすべて反映されるか、どれも反映されないかを保証する性質。|原子性保证一个事务中的操作要么全部生效，要么全部撤销。|转账过程中入账失败时，先前的扣款也会撤销。
consistency|一貫性（ACID）|Consistency|一致性|処理の前後でデータが定義済みの制約や整合条件を満たす性質。|事务的一致性要求合法的初始状态经过事务后仍满足既定规则。|订单引用的顾客编号在事务完成后依然指向存在的顾客。
isolation|独立性（ACID）|Isolation|隔离性|同時に行われる処理が互いに与える影響を、定められた水準で制限する性質。|隔离性限制并行事务之间看到彼此中间状态的方式。|结账事务不会读到另一事务尚未提交的价格调整。
durability|永続性（ACID）|Durability|持久性|処理の確定後は、障害が起きてもその結果が失われない性質。|持久性保证已确认的事务结果在故障后可以恢复。|顾客看到付款成功后，即使服务器随后重启也能查到付款记录。
commit|コミット（データベース）|Transaction Commit|提交事务|進行中の処理の変更を確定し、以後保持されるようにする操作。|提交确认当前事务的结果，使这些修改生效。|核对两边账户金额后提交转账事务。
rollback|ロールバック|Rollback|回滚事务|処理中の変更を取り消して、開始時などの以前の状態へ戻す操作。|回滚撤销尚未提交的更改，可撤销整个事务或退回指定保存点。|发现部分借阅记录输入错误后回滚整个批次。
savepoint|セーブポイント|Savepoint|保存点|処理を途中まで取り消す際に戻れる位置として、実行中に設定する印。|保存点给事务标记一个中间位置，可以把后续更改撤回到这里。|导入十条正确记录后设置保存点，再尝试导入有疑问的记录。
# 同時実行制御と復旧
shared-lock|共有ロック|Shared Lock|共享锁|同じ対象に複数の読取り用の確保を許し、書込み用の排他的な確保を阻む方式。|共享锁允许多个事务同时读取锁定对象，但通常阻止其他事务取得排他锁来写入。|生成报表的两个事务可同时持有某行的共享锁。
exclusive-lock|排他ロック|Exclusive Lock|排他锁|ある処理が対象を占有し、他の処理による競合する確保を許さない方式。|排他锁阻止其他事务在同一对象上获得冲突锁，常用于写操作。|修改订单状态时取得排他锁，其他更新操作要等待。
dirty-read|ダーティリード|Dirty Read|脏读|他の処理がまだ確定していない変更を読み取る現象。|脏读是读到了另一个事务尚未提交、之后可能被撤销的数据。|库存报表使用了后来被撤销的进货记录。
nonrepeatable-read|反復不能読取り|Non-repeatable Read|不可重复读|同じ処理で同じ行を二度読んだとき、別の処理の確定によって結果が変わる現象。|不可重复读指同一事务两次读取同一行，因他人提交修改或删除而看到不同结果。|第一次读取商品单价为 20 元，另一事务提交改价后再读变成 25 元。
phantom-read|ファントムリード|Phantom Read|幻读|同じ条件で行の集合を二度調べたとき、他の処理の変更で該当する行の集合が変わる現象。|幻读关注同一查询的匹配行集合变化，例如别的事务提交后新增了匹配行。|同一统计事务两次查询未付款订单，第二次多了一笔其他事务插入的订单。
wal|先行書込みログ（WAL）|Write-ahead Logging|预写日志|変更後のデータページを永続化する前に、対応する変更記録を永続化する方式。|预写日志要求先持久化恢复所需的日志，再落盘修改后的数据页。|停电后数据库根据预写日志重做尚未写入数据页的已提交修改。
checkpoint|チェックポイント（データベース）|Database Checkpoint|数据库检查点|復旧時に調べる変更記録の範囲を絞るため、処理や書込みの状態を記録する目印。|检查点记下数据库恢复所需的状态，缩短故障后需要检查的日志范围。|系统重启后，数据库利用最近检查点定位需要检查的日志。
mvcc|多版型同時実行制御（MVCC）|Multiversion Concurrency Control|多版本并发控制|同じデータの複数の版を管理し、各処理に適した版を参照させる制御。|多版本并发控制保留同一行的多个版本，让查询按其可见性规则读取数据。|一边修改库存一边读取报表时，报表可以读取符合其快照的版本。
# 索引・問い合わせ処理
index|インデックス|Database Index|数据库索引|表の行を効率よく探すため、特定の列の値と行の位置などを対応させる補助構造。|索引给数据库提供快捷查找路径，通常需要额外存储，写入时也可能要更新。|为订单编号建立索引，加速按编号查单。
composite-index|複合インデックス|Composite Index|复合索引|複数の列の値の組を使って行を探すための補助構造。|复合索引按多个字段建立。能否加速某个查询取决于字段顺序和查询条件。|用门店编号与下单时间建立索引，便于查询某店当天订单。
table-scan|全表走査|Full Table Scan|全表扫描|問い合わせに答えるため、表のデータ全体を順に調べるアクセス方式。|全表扫描直接读取表中的数据来判断哪些记录符合条件。|没有合适索引时，数据库扫描全部图书记录以筛选出版社。
execution-plan|実行計画|Query Execution Plan|查询执行计划|問い合わせを処理する際に採用する、読取りや結合の順序と方式を示すもの。|执行计划说明数据库将如何读取、筛选和连接数据。|查看某个慢查询的执行计划，确认是否发生了全表扫描。
query-optimizer|問合せ最適化器|Query Optimizer|查询优化器|同じ結果を得る複数の処理方法から、推定コストなどを基に方式を選ぶ機能。|查询优化器比较可行的执行计划并择一运行。|优化器评估订单表大小后，选择用索引查找订单。
b-tree-index|B木インデックス|B-tree Index|B 树索引|キーを順序付きの平衡木で管理し、特定の値や範囲を探せる索引。|B 树类索引按有序层级维护键，可以有效支持等值和范围查询。|用日期索引快速查询过去七天的订单。
hash-index|ハッシュインデックス|Hash Index|哈希索引|キーの値から格納先を計算し、同じ値を効率よく探す索引。|哈希索引根据键计算查找位置，适合等值查询。|快速定位编号恰好为 1008 的商品。
covering-index|カバリングインデックス|Covering Index|覆盖索引|ある問い合わせで必要な列の値をすべて保持し、索引だけで結果を得られる場合がある索引。|覆盖索引包含某个查询所需的字段，因此数据库有机会直接从索引取结果。|索引包含订单编号和状态，查状态时可以减少对原表的访问。
# データベースの種類と用途
nosql|NoSQLデータベース|NoSQL Database (Not Only SQL)|NoSQL 数据库|関係モデル以外のデータ構造を主な保存・処理方式とするデータベースの総称。|NoSQL 常解读为“不只有 SQL”，涵盖文档、键值和图等非关系数据模型。|内容管理系统用文档型 NoSQL 存储结构不同的文章。
key-value-store|キーバリューストア|Key–Value Store|键值存储|一意な識別子に対応する値を登録し、その識別子で値を取得することを中心とするデータストア。|键值存储使用键快速读写对应的值。|用会话编号读取对应的购物车内容。
document-store|ドキュメントデータベース|Document Database|文档数据库|入れ子の項目を含められる構造化された文書を単位として管理するデータベース。|文档数据库以结构化文档为单位存放数据，字段可嵌套。|把每篇文章的标题、作者及标签放在同一份文档中。
graph-db|グラフデータベース|Graph Database|图数据库|データを点とそれらを結ぶ辺で表現し、つながりをたどる検索を得意とするデータベース。|图数据库把实体和关系存成节点和边，便于查询连接路径。|从某位顾客出发查找其好友的好友。
time-series-db|時系列データベース|Time-series Database|时序数据库|時刻を伴う観測値を継続して記録し、時間範囲の検索や集計を効率化するデータベース。|时序数据库专门处理按时间记录的数据。|保存温度传感器每分钟上报的读数。
warehouse|データウェアハウス（DWH）|Data Warehouse|数据仓库|複数の業務データを統合し、主に長期的な分析に利用するデータの保管基盤。|数据仓库整合不同来源的数据，供跨业务或长期分析使用。|总部把各门店多年的交易记录整合起来分析销售趋势。
oltp|オンライントランザクション処理（OLTP）|Online Transaction Processing|联机事务处理|多数の短い取引を、発生の都度、整合性を保って処理する用途。|OLTP 面向日常业务中数量多、执行快的交易。|售票系统即时完成选座、扣库存和下单。
olap|オンライン分析処理（OLAP）|Online Analytical Processing|联机分析处理|大量のデータを複数の観点から集約し、比較や傾向の分析を行う用途。|OLAP 用于对大量数据从时间、地区等多个维度做汇总分析。|按季度和地区查看各产品线的销售变化。
