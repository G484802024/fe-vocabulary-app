# 通信モデルとデータの単位
osi|OSI基本参照モデル|Open Systems Interconnection Reference Model|OSI 参考模型|通信に必要な機能を物理的な伝送から応用まで七つの層に整理したモデル。|用七层描述开放系统通信，各层负责一类功能。|学习时把网线信号与网页服务放到不同的层来理解。
tcpip|TCP/IPモデル|Transmission Control Protocol and Internet Protocol Model|TCP/IP 模型|インターネットで使われる通信機能をリンク、インターネット、トランスポート、応用などの層に整理するモデル。|按互联网协议实际分工组织各层，常见解释为四层。|把 IP 放到互联网层，把 HTTP 放到应用层。
physical-layer|物理層|Physical Layer|物理层|物理媒体を通じてビットを信号として伝送する層。|处理电、光或无线信号等实际传输。|网线上的电信号承载各个比特。
data-link-layer|データリンク層|Data Link Layer|数据链路层|直接つながった機器間のフレーム転送を担当する層。|控制同一链路上的帧传递。|交换机在一个局域网内转发以太网帧。
network-layer|ネットワーク層|Network Layer|网络层|異なるネットワークをまたいでパケットを宛先まで転送する層。|通过逻辑寻址和路由实现跨网络传输。|路由器按目的 IP 选择下一跳。
transport-layer|トランスポート層|Transport Layer|传输层|通信する端末上のプロセス間でデータをやり取りする層。|让端系统上的应用进程交换数据，可以按协议提供可靠传输。|接收方按端口号把数据交给对应程序。
session-layer|セッション層|Session Layer|会话层|応用間の対話の開始、維持、終了などを管理する層。|在 OSI 模型中负责管理通信双方的会话。|通信模型将长时间交互的建立和结束归在这一层。
presentation-layer|プレゼンテーション層|Presentation Layer|表示层|異なるシステムで交換できるようにデータの表現や形式を調整する層。|在 OSI 模型中负责数据表示转换等工作。|通信双方按约定的字符表示交换文字。
application-layer|アプリケーション層|Application Layer|应用层|アプリケーションがネットワークサービスを使うための規約を扱う層。|为应用提供网页访问、邮件等网络通信规则。|浏览器根据 HTTP 规则与网站交互。
decapsulation|デカプセル化（ネットワーク）|Network Decapsulation|网络解封装|受信したデータから現在の層の制御情報を取り除き、取り出した内容を上位層へ渡す処理。|接收时移除本层附加的控制信息，把取出的内容交给上层处理。|网卡接收帧后，把帧中承载的 IP 数据包交给网络层。
# IPアドレスとネットワークの識別
ipv4|IPv4|Internet Protocol Version 4|互联网协议第 4 版|32ビットのアドレスで通信相手を識別するIPの版。|使用 32 位地址，常写为四组十进制数。|打印机在局域网内使用 192.168.1.20。
ipv6|IPv6|Internet Protocol Version 6|互联网协议第 6 版|128ビットのアドレスを採用し、大きなアドレス空間を持つIPの版。|使用 128 位地址，通常用冒号分隔的十六进制表示。|网站的域名可以配置第 6 版地址记录。
ip-address|IPアドレス|Internet Protocol Address|IP 地址|パケットの送り先などをネットワーク層で示す論理的な識別子。|为 IP 通信标识网络接口，便于路由转发。|电脑用服务器的 IP 地址发送跨网请求。
mac-address|MACアドレス|Media Access Control Address|MAC 地址|局所リンク上でフレームの送信元や宛先を示す識別子。|为以太网等链路标记发送或接收接口，常见长度是 48 位。|交换机用帧里的目的 MAC 地址选择出口。
public-ip|グローバルIPアドレス|Public IP Address|公网 IP 地址|インターネットで重複しないように割り当てられ、公の経路で利用できるIPアドレス。|可用于公网通信的地址，是否能从外部访问还取决于路由和防火墙。|网站部署到具有公网地址的服务器。
private-ip|プライベートIPアドレス|Private IP Address|私有 IP 地址|組織内などで自由に利用でき、公開インターネットには通常経路がないIPアドレス。|保留给内部网络使用，不在公共互联网中转发。|家用路由器给手机分配 192.168.1.10。
loopback|ループバックアドレス|Loopback Address|回环地址|外部の回線に出ず、自分自身へデータを届けるためのアドレス。|访问本机的专用地址，不需要通过外部网络。|开发者打开 127.0.0.1 查看在本机运行的网站。
link-local|リンクローカルアドレス|Link-Local Address|链路本地地址|同じリンク内だけで有効で、ルータを越えて転送されないアドレス。|只在当前链路有效，常用于自动配置和本地发现。|同一局域链路的设备使用 IPv6 链路本地地址通信。
subnet-mask|サブネットマスク|Subnet Mask|子网掩码|IPv4アドレスのネットワーク部分とホスト部分の境界をビット列で示す値。|用连续的 1 标记网络部分，用 0 标记主机部分。|掩码 255.255.255.0 表示前 24 位是网络部分。
cidr|CIDR|Classless Inter-Domain Routing|无类别域间路由|固定のアドレスクラスに従わず、可変長のプレフィックスでIPアドレスの範囲を扱う方式。|用可变的前缀长度表示和聚合 IP 地址范围。|运营商用一个 /22 前缀汇总四个相邻的 /24 网段。
# パケットと到達性
packet|パケット|Packet|数据包|通信でデータを小分けにして宛先情報などを付けた転送単位。|网络中可以独立转发的一份数据和控制信息。|一段视频会被拆成许多数据包在网络中传送。
frame|フレーム|Frame|数据帧|データリンク層で、区切りやリンク上の宛先などを含む転送単位。|在一条数据链路上传送的单位，包含链路层控制信息。|电脑将 IP 包放进以太网帧交给交换机。
segment|TCPセグメント|Transmission Control Protocol Segment|TCP 报文段|順序番号などのヘッダと任意のデータからなる信頼型トランスポートの単位。|TCP 在传输层发送的数据单位，含序号等控制字段。|网页上传时一段数据被切成多个报文段。
udp-datagram|UDPデータグラム|User Datagram Protocol Datagram|UDP 数据报|ポート番号などを含み、接続を確立しないトランスポートで扱うデータ単位。|UDP 一次交付的独立传输单位，带端口等控制信息。|小型 DNS 查询通常装在一个 UDP 数据报中。
mtu|MTU（最大転送単位）|Maximum Transmission Unit|最大传输单元|あるリンクで分割せずに運べる上位層パケットの最大長。|当前链路可直接承载的网络层数据包的最大大小。|普通以太网接口的 IP MTU 常为 1500 字节。
ttl|TTL（IPパケット）|Time to Live|生存时间|IPパケットが経路内を巡り続けないよう、中継時に減らされる値。|IPv4 路由转发时递减的值，耗尽后包会被丢弃。|路由错误形成环路时，经过若干跳的数据包会停止循环。
icmp|ICMP|Internet Control Message Protocol|互联网控制报文协议|IP通信で発生した到達不能などの通知や、疎通確認に使われるプロトコル。|为 IP 传递网络错误和诊断信息。|路由器找不到目标网络时可返回不可达通知。
arp|ARP|Address Resolution Protocol|地址解析协议|同じリンク上のIPv4アドレスに対応するリンク層アドレスを調べるプロトコル。|在当前链路中查询某个 IPv4 地址对应的 MAC 地址。|电脑发送局域网数据前先查出打印机的 MAC 地址。
ndp|NDP（近隣探索）|Neighbor Discovery Protocol|邻居发现协议|IPv6で同じリンクの近隣機器やルータを見つけ、アドレスの解決などを行う仕組み。|让 IPv6 设备发现本地邻居、路由器等并解析链路层地址。|新接入的电脑从路由器公告获取网络前缀信息。
dhcp|DHCP|Dynamic Host Configuration Protocol|动态主机配置协议|接続した端末にIPアドレスなどの設定を自動で貸し出すプロトコル。|自动给设备配置地址和相关网络参数，常按租期使用。|笔记本加入办公室网络后自动得到地址和 DNS 设置。
# 経路制御とリンク制御
static-routing|静的ルーティング|Static Routing|静态路由|運用者が設定した経路を使い、経路情報を自動で交換しない方式。|由管理员配置要走的路径。|小型分支机构把外部流量统一交给指定网关。
dynamic-routing|動的ルーティング|Dynamic Routing|动态路由|機器間で経路情報を交換し、ネットワークの変化に合わせて経路を更新する方式。|路由设备相互学习网络情况并自动更新路径。|一条线路故障后，路由器改用另一条路径。
rip|RIP|Routing Information Protocol|路由信息协议|宛先までの中継数を主な尺度として経路を選ぶ距離ベクトル型のプロトコル。|使用跳数衡量路径距离的动态路由协议。|小型教学网络用跳数比较两条可到达路径。
ospf|OSPF|Open Shortest Path First|开放最短路径优先|リンクの状態を共有し、コストが小さい経路を各ルータが求める内部経路制御プロトコル。|在自治系统内交换链路状态，各路由器据此计算路径。|企业路由器根据链路代价选择内部通信路径。
bgp|BGP|Border Gateway Protocol|边界网关协议|自律システム間で経路を交換し、経由する自律システムや方針に基づいて選ぶプロトコル。|互联网不同自治系统之间用它通告路由并按策略选路。|运营商向其他运营商通告可到达的地址前缀。
default-route|デフォルトルート|Default Route|默认路由|宛先に一致する具体的な経路が見つからないときに使う経路。|路由表中用于处理未知目的网段的兜底条目。|家庭路由器把没有专用条目的目的地发往运营商。
lpm|最長一致|Longest Prefix Match|最长前缀匹配|宛先に一致する複数の経路があるとき、ネットワーク部の一致が最も長いものを選ぶ規則。|如果多个路由前缀都匹配目的地址，优先选最长的那条。|访问指定办公子网时优先走 /24 专用路由而不是更宽泛的 /16 路由。
stp|STP（スパニングツリー）|Spanning Tree Protocol|生成树协议|冗長なリンクの一部を論理的に止め、スイッチ間のフレームのループを防ぐプロトコル。|在交换网络中选择无环的活动链路拓扑。|三个交换机围成环时会保留一条备用链路。
csma-cd|CSMA/CD|Carrier Sense Multiple Access with Collision Detection|带冲突检测的载波侦听多路访问|共用媒体が空いてから送信し、衝突を検出した場合は待って再送する方式。|旧式共享以太网先听信道，检测到碰撞后等待再发。|多台电脑共用老式集线器时避免反复同时发送。
csma-ca|CSMA/CA|Carrier Sense Multiple Access with Collision Avoidance|带冲突避免的载波侦听多路访问|共用媒体を確認し、ランダムな待ち時間などで衝突の発生を抑える方式。|无线设备先侦听信道，再用随机等待减少抢占冲突。|同一接入点附近的多台设备错开数据发送时机。
# トランスポートと通信の確認
tcp|TCP|Transmission Control Protocol|传输控制协议|接続を確立し、欠けたデータの再送や順序の調整を行うトランスポートプロトコル。|为应用提供可靠、有序的字节流传输。|浏览器通过可靠连接下载完整安装包。
udp|UDP|User Datagram Protocol|用户数据报协议|接続確立や到着確認を行わず、独立したデータ単位を送るトランスポートプロトコル。|直接发送数据报，不内置重传和顺序保障。|实时语音应用在低延迟场景下发送音频数据报。
port-number|ポート番号|Port Number|端口号|同じ端末で動く複数の通信サービスなどをトランスポート層で識別する番号。|帮助操作系统把收到的数据交给正确的应用。|服务器用 TCP 443 接收 HTTPS 连接。
well-known-port|ウェルノウンポート番号|Well-Known Port Number|知名端口号|よく使われるサービスに割り当てられる番号のうち、0から1023までの範囲。|0 至 1023 的系统端口范围，其中不少端口保留给常见服务。|传统 HTTP 默认使用 TCP 80。
ephemeral-port|エフェメラルポート|Ephemeral Port|临时端口|クライアントの通信などに、OSが短期間だけ割り当てるポート。|操作系统临时分配给连接的本地端口。|浏览器为发起一次网页访问使用一个临时源端口。
three-way|3ウェイハンドシェイク|Three-Way Handshake|三次握手|TCPで両端が開始用の制御情報を三回やり取りし、接続を確立する手順。|TCP 用 SYN、SYN-ACK、ACK 建立连接并同步初始序号。|浏览器在使用 TCP 请求网页前先建立连接。
ack|ACK（肯定応答）|Acknowledgment|确认应答|送信側に、受信したデータや制御情報を確認したことを知らせる応答。|向发送者表明接收方已经确认某些信息。|文件传输过程中，接收方报告已连续收到的一段字节。
retransmission|再送制御|Retransmission|重传控制|通信途中で失われたと判断されたデータを送り直す処理。|协议在判断数据未送达时重新发送。|下载时某段未得到确认，发送端重新发出该段。
flow-control|フロー制御|Flow Control|流量控制|受信側が処理しきれない量のデータが届かないように送信を調整する機能。|按接收端处理和缓冲能力限制发送方，避免接收端被淹没。|TCP 接收缓冲区空间变小后，发送方减少未确认的数据量。
congestion-control|輻輳制御|Congestion Control|拥塞控制|ネットワークが混雑し過ぎないよう、通信状況に応じて送信量を調整する機能。|按网络承载情况调整发送速率，减轻共享路径的拥堵。|长距离上传出现网络拥塞迹象后，发送端降低速度。
# ドメイン名と名前解決
dns|DNS|Domain Name System|域名系统|階層的な名前に対応するIPアドレスなどの情報を分散管理し、照会に答える仕組み。|以分布式方式保存域名及地址、邮件服务器等记录。|访问网站前设备查询域名对应的 IP。
fqdn|FQDN|Fully Qualified Domain Name|完全限定域名|名前の階層をルートまで省略せずに示す完全なドメイン名。|写出从具体节点到根的完整域名，绝对形式可以用末尾的点表示根。|在区文件中用 www.example.com. 表示完整名称。
dns-resolver|DNSリゾルバ|DNS Resolver|DNS 解析器|要求された名前の情報を、キャッシュや他の名前サーバへの問い合わせで得る機能。|为设备查询域名记录，可缓存和复用答案。|家庭设备向运营商的递归解析器查询域名。
authoritative-dns|権威DNSサーバ|Authoritative DNS Server|权威 DNS 服务器|担当するゾーンに登録された正式なレコードをもとに応答する名前サーバ。|负责某个区的正式 DNS 数据并直接回答相关查询。|学校在自己的权威服务器维护网站的地址记录。
a-record|Aレコード|Address Record|A 记录|DNSで、名前に対応する32ビットのIPアドレスを登録するレコード。|把主机名指向 IPv4 地址。|把网站域名指向服务器的 IPv4 地址。
aaaa-record|AAAAレコード|IPv6 Address Record|AAAA 记录|DNSで、名前に対応する128ビットのIPアドレスを登録するレコード。|把主机名指向 IPv6 地址。|给支持 IPv6 的网站添加地址记录。
cname-record|CNAMEレコード|Canonical Name Record|别名记录|DNSで、ある名前を別の正規名の別名として登録するレコード。|让一个域名作为另一个域名的别名。|把图片子域名设为内容分发服务域名的别名。
mx-record|MXレコード|Mail Exchange Record|邮件交换记录|DNSで、そのドメイン宛てのメールを受け取るサーバの名前を示すレコード。|公布负责接收某域邮件的服务器及优先级。|邮件服务器查询公司域名的记录来决定投递地点。
ptr-record|PTRレコード|Pointer Record|反向解析记录|逆引きDNSで、アドレスに対応する名前を示すために用いるレコード。|在反向 DNS 区中把 IP 地址关联到主机名。|管理员从服务器的公网 IP 反查其邮件主机名。
ns-record|NSレコード|Name Server Record|域名服务器记录|DNSで、あるゾーンの名前解決を担当する権威サーバの名前を示すレコード。|指定某个 DNS 区的权威域名服务器，可用于将子域交给其他服务器管理。|将学校的实验室子域委派给实验室自行维护的域名服务器。
# Web通信
http|HTTP|Hypertext Transfer Protocol|超文本传输协议|クライアントの要求とサーバの応答によってWebの資源をやり取りするプロトコル。|定义客户端请求与服务器响应的格式和语义。|浏览器请求网页，服务器返回 HTML 内容。
https|HTTPS|Hypertext Transfer Protocol Secure|安全超文本传输协议|Webの要求と応答をTLSで保護してやり取りする通信方式。|在 TLS 保护下使用 HTTP，提供加密、完整性和服务端身份认证等。|使用购物网站时，订单内容经加密连接发送。
url|URL|Uniform Resource Locator|统一资源定位符|Webページなどについて、場所と取得方法を示す識別子。|说明资源的位置和访问方式，例如协议、主机名和路径。|把课程页面地址复制给同学就能打开同一页面。
http-method|HTTPメソッド|HTTP Method|HTTP 请求方法|Webの要求で、対象資源に対して行いたい操作の種類を示す要素。|告诉服务器客户端想做哪一类操作。|浏览器请求显示页面时使用 GET。
get|GETメソッド|HTTP GET Method|GET 方法|対象資源の現在の表現を取得することを意図したWeb要求。|用于读取目标资源的表示，语义上不请求修改资源。|浏览器获取一张商品图片。
post|POSTメソッド|HTTP POST Method|POST 方法|要求に含めたデータを対象資源の規則に従って処理するよう求めるWeb要求。|提交数据，请目标资源按自身逻辑处理。|报名网页把表单数据提交给服务器。
http-header|HTTPヘッダ|HTTP Header|HTTP 头字段|要求や応答で、メッセージやデータの扱いに関する補足情報を運ぶ項目。|传递内容类型、缓存规则等控制和描述信息。|服务器用 Content-Type 表示响应是 JSON。
http-status|HTTPステータスコード|HTTP Status Code|HTTP 状态码|Web要求に対する結果を分類して示す三桁の番号。|以三位数字说明请求成功、重定向或发生错误等结果。|请求的路径不存在时，网站通常返回 404。
